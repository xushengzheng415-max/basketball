# 机构账号开户、登录与模块授权规则

> 文档状态：第一阶段规划稿（关键边界已确认）  
> 日期：2026-07-28  
> 正式产品名称：赛小蜂篮球丨赛训经营增长平台  
> 适用范围：平台方后台、机构 PC 后台、机构小程序、服务号

## 一、已确认规则

1. 机构账号由用户自行申请开通，平台方不逐户人工创建账号。
2. 所有 PC 后台统一使用手机号加短信验证码登录，不设置登录密码，暂不建设 PC 微信扫码登录。
3. 服务号承担机构入驻申请、账号找回通知、外部人员邀请和资料提交入口。
4. 基础机构账号免费，赛事中心免费但由机构自行选择启用。
5. 交易与财务归入付费“教务经营”模块；招生增长按后续产品授权规划开通。
6. 授权码绑定机构和模块，不绑定负责人个人，也不能作为短信登录验证码。
7. 平台方后台与机构方后台使用独立入口、独立角色和独立数据权限。
8. PC 后台负责配置、调度、审核和汇总；小程序负责机构内部日常执行；服务号负责外部人员进入。

## 二、四类入口

| 入口 | 使用人 | 主要用途 | 是否允许管理其他机构 |
|---|---|---|---|
| 平台方后台 | 平台运营、客服、审计人员 | 机构监管、授权码、模块权益、异常处理 | 按平台角色授权 |
| 机构 PC 后台 | 机构负责人、校区负责人、教务、赛事、财务人员 | 机构管理、赛事调度、教务经营、审核与报表 | 否 |
| 机构小程序 | 机构负责人、教练、现场执行人员 | 点名、课消、评价、计分、检录、现场任务 | 否 |
| 服务号 | 机构申请人、外部教练、裁判、球员及家长 | 自助开户、邀请进入、资料提交、绑定确认 | 否 |

机构负责人购买或激活服务后仍然只是机构管理员，不会因此获得平台方后台权限。

## 三、自助开户注册流程

### 3.1 新机构

```text
关注服务号
→ 进入“机构入驻”
→ 验证手机号
→ 填写机构名称、负责人、所在地区和首个校区
→ 验证负责人手机号
→ 同意服务协议和数据处理规则
→ 创建机构基础账号
→ 默认开通免费赛事中心
→ 登录机构 PC 后台
```

开户成功后自动建立：

- 一个机构主体；
- 一个默认校区；
- 一个机构超级管理员；
- 基础组织与权限能力；
- 已生效的免费赛事中心权益。

赛事中心随机构开户默认启用，不再增加模块选择步骤。教务经营仍需购买授权码后单独激活。

第一阶段只创建一个默认校区。多校区的数据结构、接口和权限范围预留，但暂不提供多校区管理与统计页面。

平台方不参与日常开户操作，但可以在平台后台查看开户记录、处理重名或违规机构、冻结异常账号。

### 3.2 已有机构新增员工

```text
机构负责人在 PC 后台创建邀请
→ 选择校区、角色和有效期
→ 员工在小程序或服务号确认
→ 绑定个人微信身份
→ 形成机构成员关系
→ 按角色使用小程序
```

负责人绑定的是员工与本机构的成员关系，不是占有员工的微信账号。

## 四、登录规则

### 4.1 机构 PC 后台

- 唯一登录方式：手机号加短信验证码。
- 手机号用于识别个人账号，验证码用于完成本次登录。
- 账号归属：机构成员个人账号，不设机构共用密码。
- 登录后必须确认当前机构；同一人属于多个机构时先选择机构。
- 用户首次完成 PC 登录绑定时，系统询问其高频使用场景：“赛事模块”或“教培功能模块”。
- 该选择只记录默认工作台，不改变账号角色、模块权益或数据权限；用户后续可在工作台切换器中随时切换，并可在设置中修改默认工作台。
- 超级管理员、财务人员执行敏感操作时可再次发送短信验证码确认。
- PC 微信扫码登录列为后续评估项，本阶段不配置。

### 4.2 可信设备与四位锁屏码

为减少短信验证码费用，同时防止办公室无人值守电脑泄露机构数据，PC 后台采用“首次短信登录＋可信设备＋应用锁”。

```text
首次登录或新设备
→ 手机号加短信验证码
→ 用户选择“信任此设备”
→ 设置本账户在本设备上的四位锁屏码
→ 设备保持登录 30 天
→ 无操作 10 分钟自动锁屏
→ 再次打开只需输入四位锁屏码
```

产品规则：

- 四位锁屏码只用于已验证设备解锁，不能用于新设备登录；
- 锁屏码按“用户＋设备”单独设置，不在不同电脑之间共用；
- 连续输错 5 次后撤销本设备信任，必须重新短信验证；
- 可信设备有效期暂定 30 天，到期后重新短信验证；
- 浏览器数据被清除、设备环境明显变化或账号被停用时，立即失去可信状态；
- 修改手机号、变更机构超级管理员、调整商户号、退款、敏感导出和高风险权限变更时，仍需短信二次验证；
- 用户可在“账号安全—登录设备”查看设备并远程退出；
- 机构超级管理员停用成员后，该成员全部 PC 会话和设备锁立即失效；
- 公共电脑和临时电脑不得勾选“信任此设备”。

锁屏码不得明文保存、展示或找回，只允许重置。服务端会话仍需设置有效期并支持主动失效，不能只依靠前端遮罩。

### 4.3 防偷窥能力

- 页面右上角提供“一键锁屏”；
- 无操作 10 分钟自动锁屏，并在锁屏前提示；
- 浏览器重新打开且可信会话有效时，先显示应用锁，不直接展示业务数据；
- 可开启隐私模式，对手机号、家长联系方式、金额和关键经营指标进行脱敏；
- 敏感页面显示账号、机构和时间水印；
- 浏览器切换到后台时可立即遮挡页面内容；
- Web 端不能可靠禁止系统截图，因此防护重点是锁屏、脱敏、水印和操作审计。

### 4.4 小程序

- 继续使用现有微信授权能力。
- 微信 `openid` 只作为登录凭证，不能直接等同于机构账号。
- 小程序身份通过机构成员关系关联到机构、校区和角色。

### 4.5 平台方后台

- 与机构 PC 后台分开登录。
- 购买服务或持有授权码不会产生平台管理员身份。
- 同一自然人如确实兼任平台人员和机构负责人，也必须从两个入口进入，并分别校验角色。
- 平台方后台入口在官网底部

## 五、账号与归属权

| 对象 | 归属 | 离职或负责人变更后的处理 |
|---|---|---|
| 个人登录账号 | 个人 | 保留个人账号，取消原机构成员关系 |
| 机构主体 | 机构 | 不随负责人账号转移或删除 |
| 校区、员工岗位 | 机构 | 由机构超级管理员维护 |
| 赛事、球队、赛程、赛果 | 创建或承办机构 | 继续保留在机构空间 |
| 学员、课程、课包、交易、财务数据 | 机构 | 继续保留，按权限访问 |
| 模块授权 | 机构 | 负责人更换后仍有效 |
| 操作日志 | 平台/机构审计空间 | 不因员工离职而删除 |

负责人移交只改变“谁是机构超级管理员”，不迁移机构数据和模块权益。

## 六、模块授权

| 模块 | 开通方式 | 费用 | 开通后的主要能力 |
|---|---|---:|---|
| 机构基础后台 | 服务号自助开户 | 免费 | 机构资料、默认校区、账号、成员与基础设置 |
| 赛事中心 | 机构自行启用 | 免费 | 赛事、球队、球员、赛程、现场任务、基础计分、赛果与球队级报表 |
| 教务经营 | 购买授权码激活 | 付费 | 课程、课包、排课、学员、点名、课消、评价、订单、收款、退款、流水、对账与财务报表 |
| 招生增长 | 随对应授权包开通 | 付费 | CRM、试听、续费、家长运营、内容转介绍、经营归因 |

“授权码”是业务激活码，不是系统 API 密钥。授权码必须具备模块、版本、有效期、可用次数和状态。

### 6.1 激活流程

```text
机构购买授权码
→ 机构超级管理员进入“模块与授权”
→ 输入授权码
→ 系统校验模块、期限、状态和适用机构
→ 用户确认授权内容
→ 权益绑定 organization_id
→ 菜单、接口和数据权限同时生效
```

只隐藏菜单不等于授权控制。所有付费接口必须再次校验机构模块权益。

## 七、核心身份模型

后续系统不得继续只用小程序 `openid` 作为业务主键，建议建立：

- `user_id`：统一个人身份；
- `organization_id`：机构身份；
- `campus_id`：校区身份；
- `membership_id`：个人与机构的成员关系；
- `role_id`：角色；
- `entitlement_id`：机构模块权益；
- `external_profile_id`：外部人员资料；
- `assignment_id`：外部人员的指定赛事或场次任务。

PC 账号、手机号、微信 `openid`、可用时的 `unionid` 都是登录凭证或关联标识，不能替代 `user_id`。

## 八、账号状态

### 8.1 机构状态

`待完成资料 → 正常 → 受限 → 冻结 → 注销`

### 8.2 成员状态

`待接受邀请 → 在职启用 → 暂停 → 已退出`

### 8.3 模块状态

`未启用 → 试用/正式启用 → 即将到期 → 已到期 → 已停用`

赛事中心属于免费模块，不设置付费到期，但可以由机构主动停用或由平台因违规冻结。

球员数据统计不作为独立机构模块出售。平台按场次自动生成主队、客队两份统计任务，分别分发给双方主教练自主选择是否记录；主裁判核验通过后，数据进入统一平台并按球队权限展示。该数据不得自动用于官方 MVP 等个人奖项。收费、定价和收益规则另行确认，不沿用旧专职记录员分账方案作为当前开发依据。

## 九、安全与验收底线

1. 机构只能访问当前 `organization_id` 下的数据。
2. 短信验证码必须设置有效期、发送频率、错误次数和登录风险限制。
3. 授权码不得写入页面源码或日志，使用后不可再次兑换。
4. 平台客服查看机构数据必须有权限和审计记录。
5. 成员被停用后，PC 和小程序会话都应失效。
6. 负责人变更后，原负责人不再拥有超级管理员权限。
7. 免费赛事与付费教务的菜单、接口、数据表和导出权限必须同时隔离。
8. 可信设备、四位锁屏码和会话有效期必须由服务端共同校验。
9. 锁屏码连续输错 5 次后必须重新进行短信验证。
