# 动宝教务系统全功能拆解与赛小蜂产品对标

> 报告基准日：2026-08-01  
> 用途：赛小蜂篮球产品路线图决策  
> 对标策略：篮球专精切入，不按功能数量逐项复刻动宝  
> 调研边界：本版只使用公开网页、赛小蜂本地代码、产品文档、开发记录和 UI 3.0 原型清单；未注册、未登录动宝，未验证其实际套餐权限、后台交互、接口、性能和售后承诺。

## 1. 管理结论

动宝的公开产品边界已经超过“排课消课工具”。它把招生获客、销售跟进、教务执行、教学内容、家校互动、续费、收费财务、多校区、体测、员工考核和经营报表放在同一套系统里。2026 年的官方内容又增加了“校长分身”待办引擎、九维教练薪酬、空中分账、AI 课评、AI 学情、AI 摄像头、AI 智能体、随堂测评和心率臂带等说法。后面这些信息来自供应商自己的新闻和产品说明，能证明动宝正在公开销售或宣传这些能力，不能替代实际试用验收。

赛小蜂当前不是同成熟度的通用教务系统。仓库已经有赛事、球队球员、横屏计分、MC、教练教务、校区负责人端和 PC 经营后台等页面，也保留了比赛结果、周期报告、支付等云函数；但不少教务、CRM、财务和服务号能力仍是体验页、静态数据或高保真原型。尤其是 `native-dist/pages/campus-manager/` 下的校区经营页面没有发现业务云函数调用，不能仅凭页面数量认定为可上线 SaaS。

因此，赛小蜂不宜用“比动宝多几个教务菜单”作为竞争目标。更可行的路径是：

1. 先把单校区的学员、课程、班级、排课、点名课消、订单和续费任务做成真实数据闭环。
2. 保留赛事球员与教务学员的身份边界，通过明确映射把训练和比赛数据连起来。
3. 用篮球赛事组织、横屏计分、球员技术统计、三席协同和赛后家长报告建立动宝公开资料中没有出现的专业壁垒。
4. 多校区、体测、商城库存、智能硬件和 AI 后置；只有客户需求、数据基础和交付能力达到门槛后再建设。

## 6. 差距矩阵

### 6.1 动宝领先

1. 多班型、预约制和多方式签到。
2. 课时、课程卡、跨校区串课和多校区治理。
3. 招生活动、线索池、销售跟进和试听转化。
4. 多轮续费提醒和过程任务。
5. 标准化教案、作业、双向评价和家校互动。
6. 国标、专项、随堂、体态和硬件测评体系。
7. 积分、商城、商品和库存。
8. 收费、流水、对账和经营统计。
9. 员工绩效、目标和官方宣称的薪酬引擎。
10. 上线培训、数据导入和长期交付经验的公开呈现。

### 6.2 赛小蜂领先

1. 篮球赛事空间、组别、赛制、报名和资格审核。
2. 自动排赛、多组别日历、场馆和场次管理设计。
3. 手机与 PAD 统一横屏计分台。
4. 比分、时钟、节次、暂停、犯规、换人、撤销和赛果。
5. 球员得分归属和个人技术统计。
6. 主控、统计和 MC 三席协同与接管边界。
7. 外请现场人员按赛事/场次授权，不污染机构员工库。
8. 主客队数据统计任务、双方教练自愿记录、裁判核验和分队发布模型。

### 6.3 双方接近但成熟度不同

1. 学员、课程、班级和排课：赛小蜂原型接近，动宝公开产品化程度更高。
2. 教练课表、点名和评价：赛小蜂有体验实现，动宝覆盖更广。
3. 续费风险和家长运营：赛小蜂有设计，动宝已有公开流程。
4. 财务流水和经营报表：赛小蜂有完整页面方向，动宝公开体系更成熟。
5. 机构、员工和权限：双方都有产品表达，赛小蜂服务端实现仍不足。
6. 成长报告：动宝偏教学/体测，赛小蜂有机会融合训练与比赛。

### 6.4 赛小蜂近期不应跟进

1. 通用考级平台和师资证书体系。
2. 体态、足部、微量元素等健康检测。
3. 自研人脸闸机、指纹机、门禁和灯控硬件。
4. 重型积分商城和通用商品库存。
5. 每机构独立部署的小程序和私有化加盟平台。
6. 在源数据未稳定前建设 AI 智能体和自动训练建议。
7. 为追求功能数量同时上线全部班型、卡型和促销玩法。

## 7. 赛小蜂路线图

### 7.1 P0：单校区核心教务经营闭环

#### P0-1 统一身份、租户、权限和数据边界

- 用户价值：机构账号只能看到本机构数据；教练、校区负责人和赛事负责人各用自己的账号。
- 依赖：机构、成员、角色、模块权益、校区/赛事/个人数据范围和服务端校验。
- 不做的代价：任何教务、财务和赛事扩展都会积累越权和串数据风险。

#### P0-2 学员—课程—班级—课次主数据

- 用户价值：机构能完成建档、报名、分班和排课，不再依赖静态页面。
- 依赖：唯一学员与监护人关系、课程版本、班级、教练、场地、重复课规则和冲突检测。
- 不做的代价：点名、课消、财务和报表都没有可信来源。

#### P0-3 点名、请假、补课、课消和异常冲正

- 用户价值：教练在小程序完成日常执行，负责人能看结果并处理异常。
- 依赖：课次状态机、出勤状态、请假规则、课时流水、冲正和操作日志。
- 不做的代价：剩余课时和收入数据不可核对，续费提醒也会失真。

#### P0-4 订单、机构收款、退款和基础对账

- 用户价值：课程报名、支付、退款和权益变化能对上。
- 依赖：订单、支付状态、机构商户号、原路退款、线下登记、课时入账和差异列表。
- 不做的代价：赛小蜂仍只是教务原型，无法承接真实经营。

#### P0-5 通知事件和基础续费任务

- 用户价值：课前、变更、签到、剩余课时和续费不会只靠员工记忆。
- 依赖：业务事件中心、模板、接收人、发送记录、阈值和责任人。
- 不做的代价：家长感知和续费执行仍依赖微信群和人工表格。

#### P0-6 教务学员与赛事球员映射

- 用户价值：同一个孩子可关联训练与比赛记录，又不会把外部参赛球员自动变成付费学员。
- 依赖：两套身份主表、显式确认、监护人验证和字段授权。
- 不做的代价：赛小蜂最有价值的赛训连接无法形成，或出现隐私和数据污染。

### 7.2 P1：把训练和比赛变成家长价值与增长动作

#### P1-1 篮球成长档案和家长报告

- 用户价值：家长在一份报告里看到出勤、课堂评价、训练测评和比赛表现。
- 依赖：P0 主数据、球员映射、报告模板和可解释指标。
- 不做的代价：赛小蜂会退化为“教务 + 计分”两个孤立工具，差异化无法转成续费理由。

#### P1-2 招生 CRM、试听和续费闭环

- 用户价值：试听线索有人负责，反馈能转报名，续费风险能转任务。
- 依赖：线索、负责人、阶段、试听课次、跟进记录、失败原因和订单关联。
- 不做的代价：机构仍需在外部表格管理最接近收入的流程。

#### P1-3 赛事内容与转介绍

- 用户价值：赛程、比分、球员卡、战报和成长报告成为可分享的篮球内容。
- 依赖：内容授权、未成年人隐私、分享落地页和线索归因。
- 不做的代价：赛小蜂赛事数据只服务现场，不能沉淀机构品牌和新客。

#### P1-4 教练执行质量和经营归因

- 用户价值：负责人能看到教练的课次、出勤、评价、任务和家长反馈，并下钻到原记录。
- 依赖：统一指标口径、缺失数据提示和审计。
- 不做的代价：经营大屏继续停留在演示数字，无法指导管理。

#### P1-5 赛事高级能力产品化

- 用户价值：主办方能把赛事从报名、排程、现场任务、三席计分做到赛果复核和家长报告。
- 依赖：实时同步、席位租约、离线重试、冲突处理、事件审计和服务号授权。
- 不做的代价：已有高保真赛事原型不能形成稳定商业能力。

### 7.3 P2：达到明确门槛后再扩展

| 候选能力 | 启动门槛 | 推荐做法 |
|---|---|---|
| 多校区 | 至少有 3 家付费机构提出跨校区课程、人员和结算需求 | 先做 2—5 校区；统一主数据和口径，再做总部排名 |
| 篮球专项测评 | P1 成长档案已有稳定使用，教练愿意持续录入 | 先做少量篮球专项指标和随堂测评，后接国标体测 |
| 预约团课/私教 | 真实客户的容量、取消、候补和扣费规则明确 | 按班型插件扩展，不污染固定班主流程 |
| 储值卡/会籍卡 | 课程课次卡稳定且财务能处理余额与退款 | 建独立权益账本，不用课时字段硬兼容 |
| 积分和商城 | 机构有持续运营人员，且能证明奖励成本和使用频率 | 先人工礼品核销，再决定是否建库存 |
| 心率/签到硬件 | 有稳定供应商 SDK、设备准确度和合规协议 | 只做集成，不自研硬件 |
| AI 课评/分析 | 结构化训练和经营数据充足，人工审核流程稳定 | 输出必须可追溯、可编辑、可关闭 |

## 9. 一页式管理摘要

### 动宝最强的五项

1. 招生—试听—报名—续费的通用增长链。
2. 班级、预约、排课、签到、课消和跨校区串课。
3. 教案、作业、评价、成长档案和家长端。
4. 国标、专项、随堂和硬件测评体系。
5. 多校区、过程任务、经营报表和收费财务的公开产品覆盖。

### 赛小蜂最强的五项

1. 篮球赛事从组别、赛制、报名到赛果的完整设计。
2. 适合手机和 PAD 的横屏计分台。
3. 比分、时钟、节次、暂停、犯规、换人和事件修正。
4. 主控、球员统计和 MC 三席协同。
5. 球员比赛数据、赛后报告和数据包商业模式。

### 当前最大的五个缺口

1. 教务页面多、真实主数据和云端业务闭环少。
2. 课时账本、异常冲正、退款和对账尚未正式落地。
3. 家长端、通知和续费任务没有形成统一入口。
4. CRM、试听、内容转介绍和经营归因仍以原型为主。
5. 多校区、体测、卡型、商城和硬件与动宝存在明显功能差距。

### 建议顺序

```text
租户权限与主数据
→ 单校区课程/班级/排课
→ 点名/请假/补课/课消账本
→ 订单/退款/基础对账
→ 学员与赛事球员映射
→ 训练+比赛成长报告
→ 试听/续费/家长运营
→ 赛事高级协同正式产品化
→ 按客户门槛扩展多校区、测评和硬件
```

最终判断：动宝更像一套经过多年扩展的通用体培经营 ERP；赛小蜂更适合从篮球赛事与现场数据切入，再补齐机构每天必须使用的教务经营底座。赛小蜂若正面追赶动宝的全部通用功能，会把资源消耗在多校区、商城、考级和硬件等非优势领域；若只保留计分，又无法承接机构长期经营。单校区教务闭环与篮球赛训数据相连，是两者之间最可执行的产品位置。
