# 通用赛事赛程编排与排赛逻辑

> 适用于篮球、足球等多项目赛事。赛制决定对阵关系；排赛决定比赛日期、时间和场地。
>
> 版本：V1.0｜更新日期：2026-08-22

## 1. 排赛引擎的职责

- 读取已保存的赛制、抽签、场序、晋级依赖和比赛资源。
- 为每场比赛分配日期、开赛时间、场馆、球场和现场任务入口。
- 保存后向日历、组别竞赛日程、现场执行、赛果和对阵图同步同一份场序数据。
- 不得通过调整时间或场地改变场序、对阵来源和晋级关系；赛制变更才需要清空关联抽签和赛程。

## 2. 排赛输入

| 类别 | 必填信息 |
| --- | --- |
| 比赛拓扑 | 场序、阶段、轮次、主客来源、前置场序、名次线 |
| 比赛日 | 可用日期，上午、下午与可选晚间时段 |
| 场地资源 | 场馆、球场、启用状态、适用组别、单场时长、场间缓冲 |
| 队伍约束 | 同一队单日频次、最少休息、阶段依赖 |
| 赛事规则 | 关键场次是否单场地、项目与年龄组的默认时长 |

## 3. 场地独立资源配置

每片场地单独配置比赛日与时段，而不是全赛事共用一套时段。

1. 绑定可承办组别，例如球场1、2承办 U8/U10，球场3、4承办 U12。
2. 设置该场地单场比赛时长和场间缓冲。
3. 分别设置上午、下午的开赛和结束时间；晚间可按需开启。
4. 支持手动新增、编辑和删除某一天的开赛时间，实时重算该场地可容纳场次。

青少年篮球默认建议：U8/U10为40分钟比赛+10分钟缓冲（50分钟时隙）；U12及以上为50分钟比赛+10分钟缓冲（60分钟时隙）。足球只替换各年龄段时长、缓冲与场地适用范围。

## 4. 自动排赛硬约束

1. 同一球场、同一时间只能有一场比赛。
2. 同一队伍不能出现在同一时隙的两场比赛中。
3. 后续阶段必须晚于全部来源场次；小组排名或前一轮未结束时，不得排入实际晋级球队。
4. 青少年默认同一队同一上午最多1场、同一下午最多1场；如放宽须主办方明确确认。
5. 同一队两场之间必须满足最低休息时间，跨午间或跨日优先。
6. 仅可把比赛安排到适用组别的场地与时隙。
7. 半决赛、决赛、三四名决赛默认单场地串行，主办方可手动改为并行。

## 5. 自动排赛流程

1. 按依赖拓扑排序：小组赛/首轮淘汰 → 下一轮 → 名次赛与决赛。
2. 为每个“日期 × 场地”生成可用时隙，时隙长度取该场地适用组别的单场时长和缓冲。
3. 逐场寻找最早的合法时隙，依次校验场地、队伍、休息、阶段依赖和组别适用范围。
4. 资源不足时保留未排场次与具体原因，禁止用冲突赛程凑满。
5. 输出资源摘要：比赛日数、每场地可用/已用场次、未排场次和冲突原因。
6. 主办方确认后保存；所有下游模块以场序为唯一关联键。

## 6. 资源不足提示与建议

当在“每队上午最多一场、下午最多一场”的限制下无法完成赛程，按以下优先级给出建议：

1. 增加比赛日，优先保证青少年恢复时间。
2. 开启晚间时段，适用于必须压缩赛期的赛事。
3. 延长上午或下午结束时间。
4. 在规程允许范围内缩短缓冲或提前开赛。
5. 增加可用球场。

提示文案：

> 按当前队伍休息和阶段依赖规则，现有资源无法完成赛程。建议增加比赛日；如必须在当前天数内完成，可开启晚间时段、增加场地或调整缓冲。系统不会自动将小组赛未结束的队伍排入半决赛。

## 7. 手动调赛规则

- 日历始终显示全部启用场地，空时隙保留列宽，避免页面变形。
- 比赛卡片支持拖入空时隙，也支持与另一场比赛交换。
- 拖拽后保留当前滚动位置；变更前实时校验硬约束。
- 空时隙可用结构化下拉项新增场次：日期、时间、场地、阶段、轮次、组别、主队、客队。
- 保存后同步更新赛程日历、组别静态竞赛日程、现场任务与赛果；不改变既有场序。

## 8. 视图与导出规则

1. 赛事日历是全部组别共用的操作主页面。
2. 静态竞赛日程按组别分别生成、预览和导出，U8、U9、U12不混排。
3. 组别与分组分列：`U8男子组`为组别，`A组/B组`为分组；无分组时分组为空。
4. 淘汰和排位赛使用“场序X胜者/负者”展示来源，保证赛程、赛果和对阵图互相可追溯。

## 9. 最小数据约定与验收

每场比赛至少保存：`matchNo`、`date`、`startTime`、`venueId`、`courtId`、`competitionGroup`、`pool`、`phase`、`roundName`、`homeSource`、`awaySource`、`dependencyMatchNos`、`durationMinutes`、`bufferMinutes`、`scheduleStatus`。

验收必须覆盖：不同组别不同场地/时长并行排赛；同队上午或下午不重复；后续场次不早于来源场次；资源不足给出明确建议；拖拽、交换、新增并保存后所有下游视图同步；按组别导出的规程不混入其他组别。
