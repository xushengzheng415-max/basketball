# 企业微信渠道欢迎语自建应用配置

## 目标

- 客户通过公众号文章、官网或活动物料中的渠道二维码添加赛小蜂企微时，自动识别渠道、添加企业客户标签并发送渠道欢迎语。
- 赛小蜂成员从客户群中主动添加客户时，不自动发送渠道欢迎语。
- 保留各客户群自己的入群欢迎语，避免把“加客户欢迎语”和“入群欢迎语”混为一套规则。

## 实现边界

企微客户单聊不开放任意关键词机器人自动回复。本方案把身份或渠道选择提前到“添加企微之前”，依靠「联系我」方式的 `state` 参数识别来源。

第一阶段只区分：

1. 带渠道参数的扫码客户：执行打标签和欢迎语。
2. 无匹配渠道参数的主动添加客户：不执行任何欢迎语。

## 云函数

- 函数目录：`cloudfunctions/sxWecomCustomerRouter`
- 建议 HTTP 路由：`/sxWecomCustomerRouter`
- 入口：`index.main`
- 建议运行时：Node.js 16 或更高版本
- 建议超时：10 秒
- 对外回调必须使用 HTTPS。

## 必需环境变量

| 变量 | 说明 |
|---|---|
| `WECOM_ROUTER_ENABLED` | 初次部署设为 `false`，完成回调验证和测试后改为 `true` |
| `WECOM_CORP_ID` | 企业 ID |
| `WECOM_CONTACT_SECRET` | 客户联系 Secret，禁止写入仓库或日志 |
| `WECOM_CALLBACK_TOKEN` | 回调 Token，由管理员生成并保存在云函数环境变量 |
| `WECOM_ENCODING_AES_KEY` | 43 位回调 EncodingAESKey，禁止写入仓库或日志 |
| `WECOM_CHANNEL_RULES_JSON` | 渠道规则 JSON |

示例只使用占位值，真实标签 ID、图片 URL 和密钥不得写入仓库：

```json
[
  {
    "state": "sxf_article_entry",
    "tagIds": ["企业客户标签ID"],
    "welcome": {
      "text": "您好，欢迎联系赛小蜂篮球。请根据您的身份选择对应交流群。",
      "attachments": [
        {
          "msgtype": "image",
          "image": {
            "pic_url": "https://公开可访问的机构群活码图片地址"
          }
        },
        {
          "msgtype": "image",
          "image": {
            "pic_url": "https://公开可访问的赛事群活码图片地址"
          }
        }
      ]
    }
  }
]
```

## 企微后台配置顺序

1. 在“应用管理”中创建企业内部自建应用，名称建议为“赛小蜂客户分流”，可见范围只选当前承接成员。
2. 在“客户联系”的 API 配置中将该应用加入可调用应用。
3. 部署云函数和 HTTP 路由，先将 `WECOM_ROUTER_ENABLED=false`。
4. 在客户联系 API 页面配置接收事件服务器：回调 URL、Token、EncodingAESKey。
5. 完成企微 GET 回调验证后，再创建带 `state` 的渠道「联系我」二维码。
6. 删除或停用绑定承接成员的企微原生通用“加客户欢迎语”。如果通用欢迎语仍在生效，企微可能不会返回自建欢迎语所需的 `WelcomeCode`。
7. 用外部微信测试账号扫码添加，确认渠道标签和欢迎语正常后，将 `WECOM_ROUTER_ENABLED=true`。
8. 从客户群主动添加另一测试客户，确认没有渠道欢迎语。

## 创建带渠道参数的「联系我」二维码

脚本：`tools/wecom-create-contact-way.js`

脚本默认只预览配置，不会创建二维码。运行时通过进程环境变量提供敏感配置，禁止把 Secret 写入脚本、命令历史、仓库文件或日志。

必需变量：

- `WECOM_CORP_ID`
- `WECOM_CONTACT_SECRET`
- `WECOM_CONTACT_USER_ID`
- `WECOM_CONTACT_STATE`，第一阶段建议为 `sxf_article_entry`
- `WECOM_APPLY=true`，只有明确执行创建时才设置

## 安全要求

- 只接受通过 Token、时间戳、Nonce 和消息密文校验的企微回调。
- 使用 EncodingAESKey 解密后必须核对接收方 CorpID。
- 不在日志中记录 Secret、AccessToken、WelcomeCode、ExternalUserID 或客户个人信息。
- 渠道规则仅处理明确列出的 `state`；没有匹配 `state` 的事件直接忽略。
- 欢迎语最多保留 9 个附件。
- 回调失败可由企微重试；标签操作需保持幂等，欢迎语凭证只能使用一次。

## 本地验证

```powershell
node tools/test-wecom-customer-router.js
```

测试覆盖：

- 企业微信 AES-CBC 加解密与 PKCS#7 填充；
- SHA-1 回调签名；
- XML 字段解析；
- 渠道规则匹配；
- 匹配渠道时打标签并发送欢迎语；
- 无渠道参数的主动添加事件不调用任何企微 API。
