# 赛小蜂篮球丨赛训经营增长平台——机构 PC 后台产品边界与总体规划

> 文档状态：第一阶段规划稿（关键边界已确认）
> 日期：2026-07-28
> 当前阶段：只做产品边界与实施规划，不继续开发页面

## 一、产品定位

“赛小蜂篮球丨赛训经营增长平台”是一套由平台方后台、机构 PC 后台、机构小程序和服务号共同组成的赛训经营系统。

- 机构 PC 后台：管理、配置、调度、审核、统计和异常处理。
- 机构小程序：机构内部人员的日常执行和赛事现场操作。
- 服务号：机构自助开户、外部人员邀请、资料提交和绑定确认。
- 平台方后台：机构监管、模块授权、平台运营和审计支持。

赛事中心是机构开户注册后默认可用的免费模块；教务经营、交易财务和招生增长属于付费能力。

## 二、平台方与机构方边界

| 事项 | 平台方后台 | 机构方后台 |
|---|---|---|
| 机构开户 | 提供规则、监控和异常处理，不逐户代办 | 在服务号自助申请 |
| 机构资料 | 查看必要监管字段、处理违规 | 创建和维护本机构资料 |
| 员工账号 | 不代建普通员工 | 邀请、分配角色、停用 |
| 免费赛事 | 提供统一能力、可冻结违规使用 | 自行启用并管理本机构赛事 |
| 付费模块 | 生成授权码、维护授权产品 | 购买并激活授权码 |
| 教务与交易数据 | 默认不可直接操作 | 机构内部按角色管理 |
| 外部人员 | 提供服务号入口和身份能力 | 发起邀请、审核资料、分配场次 |
| 客服排障 | 按工单临时访问并留痕 | 发起问题和授权协助 |
| 数据导出 | 平台级汇总仅限脱敏和授权范围 | 导出本机构有权数据 |
| 账号冻结 | 可因安全、违规或欠费限制 | 可停用本机构成员 |

平台方不得无痕冒充机构管理员，机构负责人也不得进入平台运营后台。

## 三、终端职责边界

### 3.1 PC 后台

- 多条件筛选、表格和批量操作；
- 复杂排课、赛程和资源冲突处理；
- 员工、角色、校区和模块配置；
- 外部人员资料审核和赛事任务分配；
- 赛果、课消、订单和报表复核；
- 经营分析、导出和审计。

### 3.2 小程序

- 校长端：查看课程、赛事和今日增长任务；
- 教练端：点名、课消、课后评价；
- 球队和球员日常维护；
- 横屏计分、球员统计和 MC 控制；
- 现场检录、阵容确认、异常上报；
- 个人范围内的数据查看。

### 3.3 服务号

- 机构自助开户注册；
- 员工邀请确认和消息通知；
- 家长孩子成长报告邀请确认和消息通知；
- 外部球员、教练、裁判资料提交；
- 指定赛事或场次的接受、拒绝和身份绑定；
- 账号找回、授权到期和任务提醒。

服务号中的外部人员默认不进入机构教务、课消、薪酬和经营体系。

### 3.4 PC 登录、锁屏与防偷窥

机构 PC 后台统一采用以下登录会话：

```text
首次或新设备：手机号＋短信验证码
→ 选择信任设备并设置四位锁屏码
→ 设备保持登录 30 天
→ 无操作 10 分钟自动锁屏
→ 同一设备再次打开时输入四位锁屏码
```

四位锁屏码是本账户在本设备上的应用解锁码，不是登录密码。连续输错 5 次、可信设备到期、浏览器数据清除、设备风险变化或成员被停用时，必须重新短信验证。

防偷窥功能包括：

- 一键锁屏；
- 空闲自动锁屏；
- 浏览器重新打开先显示锁屏页；
- 页面失去焦点时遮挡内容；
- 手机号、金额和经营指标隐私模式；
- 敏感页面账号、机构、时间水印；
- 登录设备列表和远程退出。

修改手机号、机构负责人、商户号、退款、敏感导出和高风险权限时，仍需短信二次验证。会话、可信设备和锁屏失败次数必须由服务端校验。

## 四、免费与付费模块边界

### 4.1 免费基础能力

- 机构主体与一个默认校区；
- 机构超级管理员；
- 账号、成员邀请和基础角色；
- 模块与授权中心；
- 基础通知、操作日志和系统设置。

### 4.2 免费赛事中心

- 赛事创建、规则、组别和赛制；
- 球队、赛事球员和名单；
- 报名与资格检查；
- 场地、赛程、分组和场次；
- 内部教练指派、外部人员邀请与审核；
- 小程序现场任务下发；
- 比分、时钟、节次、暂停、球队犯规、换人和基础赛果；
- 积分榜、球队级汇总和基础导出。

免费赛事数据不得自动进入付费学员、课消、教练薪酬或经营分析。

球员数据统计仍是统一平台内的场次任务，但原统计员任务按主客队拆分后分别交由双方主教练管理。PC 只需确定主裁判并接收双方首发与替补名单；三项完成后，由现场数据管理员一键启动各角色入口。主裁判不设置名单、助教或统计口径。主教练可自主选择是否记录，并可通过通知、链接或二维码把权限分发给最多 5 名助理教练。通过适用核验的数据进入统一数据库并按球队权限展示；主办方可以查询，但不得自动用于赛事 MVP、得分王、最佳阵容等官方个人奖项。收费与分账商业方案另行确认。

### 4.3 付费教务经营

- 单校区教务管理；
- 学员、家长、教练正式档案；
- 课程管理（课程内容、课时、价格和有效期合并配置）与班级管理；
- 排课、调课、停课和冲突；
- 小程序执行点名、请假、补课、课消和课后评价；PC 只查看结果与异常记录；
- 教练课时、质量和薪酬基础；
- 成长报告和家长反馈；
- 订单、收款和支付状态；
- 退款、退课和转课；
- 财务流水和对账；
- 校区、课程、渠道等收入归属；
- 财务报表和导出。

交易与财务是教务经营的二级业务域，不单独作为一级收费模块。

收款主体必须分开：

- 平台商户号只收平台开户、授权码和平台服务费用；
- 机构业务款由机构绑定的微信支付商户号直接收取；
- 第一版一个机构绑定一个主商户号；
- 后续多校区确有独立结算需求时，再扩展多个机构商户号；
- 每笔订单固定所属商户号，退款必须按原交易通道处理。

多校区管理和对比统计只预留 `campus_id`、接口和权限范围，本阶段不开发页面，后续再确定是否作为额外付费功能。

### 4.4 付费招生增长

- 招生 CRM 和线索分配；
- 试听预约、反馈和转化；
- 续费风险与跟进任务；
- 家长运营和服务质量；
- 内容与转介绍；
- 经营归因和多校区对比。

## 五、数据边界

### 5.1 免费赛事数据

`机构 → 赛事 → 组别/赛制 → 球队 → 赛事球员 → 场次 → 现场任务 → 事件/赛果 → 报告`

赛事球员是参赛身份，不等同于付费教务中的正式学员。

### 5.2 付费教务数据

`机构 → 校区 → 学员/家长 → 课程产品 → 课包 → 班级 → 排课 → 点名/课消/评价`

### 5.3 交易数据

`机构 → 订单 → 支付/退款 → 业务项目 → 学员或赛事报名 → 财务流水`

### 5.4 转换规则

- 赛事球员转正式学员：必须由机构发起并确认，不自动转换。
- 外部教练转机构教练：必须重新建立机构成员关系。
- 外部裁判：不建立机构员工档案，只保留指定场次记录。
- 快捷比赛临时球员：默认不写入正式球员库。
- 教务学员加入赛事：可建立赛事参赛映射，但不复制或暴露无关教务数据。

## 六、内部与外部数据进入路径

### 6.1 内部员工

```text
机构 PC 创建邀请
→ 选择机构/校区/角色
→ 员工在小程序或服务号确认
→ 生成机构成员关系
→ PC 配置数据范围
→ 小程序获得日常任务
```

### 6.2 内部学员和球员

```text
付费教务：PC 建档或批量导入 → 审核 → 班级/课包绑定
免费赛事：PC 或小程序创建赛事球员 → 归入球队/赛事名单
```

两类记录可以后续关联，但不能默认合并。

### 6.3 外部人员

```text
机构 PC 发起邀请
→ 服务号进入指定邀请
→ 本人提交资料并同意用途
→ 机构 PC 审核
→ 绑定到指定赛事/场次/球队
→ 服务号接收任务和通知
→ 任务结束后权限到期
```

外部人员默认数据范围：

- 可见：本人资料、受邀赛事、受邀场次、必要的时间地点和任务信息；
- 不可见：机构学员库、课程、课消、薪酬、招生、财务和经营数据。

## 七、角色与权限矩阵

现阶段不把教务、财务、招生等职能拆成独立角色。一个人只保留一个主身份，兼职工作通过权限开关增加。工作台按机构使用场景区分，不等同于人员角色切换。

| 主身份 | PC 后台 | 小程序 | 默认数据范围 | 可增加的兼职权限 |
|---|---|---|---|---|
| 平台管理员 | 平台方后台全部监管能力 | 按需 | 全平台监管范围 | 后续再拆运营、客服、审计 |
| 机构超级管理员 | 机构全部已开通模块 | 可用 | 整个机构 | 无需额外兼职角色 |
| 校区负责人 | 本校区全部已开通模块 | 可用 | 指定校区及其赛事 | 教练执行 |
| 教练 | 默认不可登录 | 可用 | 本人课程、球队和任务 | 教务管理、招生跟进、赛事负责人 |
| 外部教练/裁判 | 不可登录 | 服务号任务入口 | 指定赛事或场次 | 无 |
| 外部球员/家长 | 不可登录 | 服务号或公开入口 | 本人/孩子赛事信息 | 无 |

其中“赛事负责人”是授予指定教练的 PC 权限，不是新的主身份：

- 获授前，教练只使用小程序；
- 获授后，教练可用本人手机号和短信验证码登录 PC；
- PC 只展示赛事中心，数据限制为指定赛区或赛事；
- 校区负责人可随时收回权限；
- 教练与校区负责人不得共用登录账号。

所有机构身份还需叠加机构、校区、赛事和个人四种数据范围。财务收款、退款和导出属于敏感权限，必须单独开关并留痕。

## 十、接口与权限边界

每个业务请求至少携带并校验：

- 当前用户 `user_id`；
- 当前机构 `organization_id`；
- 当前成员 `membership_id`；
- 当前角色和数据范围；
- 当前模块权益；
- 操作对象所属机构；
- 必要时的校区、赛事或场次范围。

禁止通过前端隐藏菜单代替服务端权限校验。

建议按领域拆分接口：

- 身份与账号；
- 机构与成员；
- 模块与授权；
- 赛事；
- 球队与球员；
- 现场任务；
- 教务；
- 交易财务；
- 招生增长；
- 报表与审计。

## 十一、第一阶段可开发范围

第一阶段目标：完成“服务号自助开户注册并默认开通免费赛事 → 机构 PC 基础框架与四步新手引导”的入口闭环；机构继续完成“赛事 PC 管理 → 小程序现场执行 → PC 赛果复核”。

### 11.1 P0 账号与基础框架

- 机构自助开户流程；
- 服务号机构开户注册页面；
- PC 手机号加短信验证码登录；
- 可信设备、四位锁屏码和自动锁屏；
- 隐私模式、敏感页面水印和远程退出设备；
- 机构、默认校区、超级管理员；
- 开户后默认启用免费赛事中心，不增加选择步骤；
- 登录后提供员工与赛事权限、课包与收款、排课、经营管理四步点击式新手引导；
- 模块与授权中心；
- 付费授权码激活入口；
- 多校区数据结构和接口预留；
- 统一 PC 框架、导航和无权限状态；
- 员工邀请、角色和基础数据范围；
- 操作日志。

## 十二、第一阶段非目标

- 不开发增长版全部教务、财务、CRM 和经营大屏；
- 不开发 PC 微信扫码登录；
- 不开发复杂在线支付和自动结算；
- 不开发多校区管理和对比统计页面，只预留接口；
- 不把外部人员转成机构正式员工；
- 不实现跨机构共享学员或财务数据；
- 不重做小程序横屏计分台；
- 不把原型截图作为页面背景或裁切成生产组件；
- 不直接沿用当前简化演示页的信息结构。

## 十三、第一阶段验收标准

1. 新机构无需平台人工操作即可完成开户注册。
2. 机构负责人和获授 PC 权限的成员可以使用手机号加短信验证码登录。
3. 同一可信设备在 30 天有效期内再次进入时无需短信验证，只需四位锁屏码。
4. PC 无操作 10 分钟后自动锁屏，不直接暴露业务数据。
5. 四位锁屏码连续输错 5 次后必须重新短信验证。
6. 服务号开户注册页面可以完成机构、负责人和默认校区创建。
7. 开户完成后自动启用免费赛事中心，不出现模块选择页。
8. 首次进入机构后台时以遮罩、高亮和指向提示引导用户点击四个真实菜单入口；点击正确目标后自动进入下一步，并允许跳过或重新播放。
9. 新机构默认只创建一个校区，多校区接口预留但页面不可用。
10. 未激活教务经营时，课程、交易和财务接口均不可访问。
11. 有效授权码可把教务经营绑定到机构。
12. 机构负责人可邀请 5 名教练并分别分配权限。
13. 教练只能看到自己的小程序任务；获授赛事负责人权限后才可进入 PC 赛事中心。
14. 外部人员只能看到指定赛事或场次。
15. 赛事从创建、排程、人员安排、现场执行到赛果复核可完整闭环。
16. 任意机构账号都无法访问其他机构数据。
17. 关键操作均有操作者、时间、机构和对象记录。
18. 页面在空数据、加载失败、无权限、模块未开通和数据冲突时有明确状态。

## 十四、已确认的高保真实现前提

1. 正式产品名称统一为“赛小蜂篮球丨赛训经营增长平台”。
2. “交易系统”归入“教务经营”，作为二级业务域。
3. 免费赛事中心随机构开户注册默认开通，不再让机构选择是否启用。
4. 免费机构账号默认创建一个校区，多校区仅预留数据结构和接口，后续再开发。
5. 第一阶段同步实现已认证服务号内的机构开户注册页面。
6. 首次登录后台按“员工与赛事权限 → 课程管理 → 班级管理 → 排课管理 → 经营管理”提供简单引导。
