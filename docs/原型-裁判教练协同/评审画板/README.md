# 裁判—双方主教练协同原型评审画板

本画板用于评审主裁判、现场数据管理员、双方主教练及每队最多 5 名助理教练的比赛日链路。主教练赛前协作流程固定为“选择记录方式 → 添加助教 → 按数据或球员分工 → 系统自动通知”；复杂的数据分工只存在于球队内部页面，不挂在裁判端。

画板按同一功能提供手机横屏和PAD横屏成对原型。两端的数据项、按钮、阵容、事件、任务、战术板和赛后汇总完全一致，只调整分栏与控件尺寸。战术板统一全屏使用指定球场底图，本方显示头像与号码，对方显示圆形号码，全部工具悬浮在球场上。

主裁判PAD控制台不参与重新设计，画板直接引用用户提供的现有控制台截图作为锁定基准。正式比赛仅禁用“显示阵容”和球员统计；机构内部比赛继续保留。

主教练分工主流程包含两种成对页面：按数据分工和按球员分工。分配状态只保留绿色可分、灰色已分并显示负责人；点击绿色即直接分配。手机与PAD规则一致。

助教加入流程也提供PAD和手机成对页面：球队已有教练可直接加入；临时助教以“转发小程序给微信好友或群”为主入口，对方确认身份后加入本场。手机号、现场二维码和历史教练保留为折叠的次级方式，不与主入口并列。

助教被添加后才进入技能分配。分工保存后系统自动通知已加入助教；待接受的临时助教在接受微信邀请后自动获得对应任务，不再展示第二个二维码或要求主教练再次发送权限。

分配页只属于赛前准备，不显示比分、比赛时间或节次。开赛后权限自动锁定，PAD与手机只提供只读进度页，不允许重新分配。

## 评审能力

- 按区段和横向链路查看全部原型；
- 点击缩略图查看完整原图并缩放；
- 从每个页面打开对应交互原型；
- 对单页保存评审意见；
- 对整段流程提出问题；
- 在备注中心筛选待处理、已解决和全部意见；
- 定位意见、标记解决或重新打开；
- 导出本地评审记录 JSON；
- 刷新全部原型截图且不丢失本地评审记录。

评审意见保存在当前浏览器 `localStorage`。更换浏览器或清除浏览器数据前，请先导出评审记录。

## 正式开发边界

当前画板用于原型确认，不代表正式代码已完成。全部原型确认后，再使用 `$yuanxing` 进入正式开发、素材拆解和 1:1 截图验收阶段。
