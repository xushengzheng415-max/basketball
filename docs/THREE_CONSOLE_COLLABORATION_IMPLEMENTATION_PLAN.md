# 赛小蜂篮球赛事中心扩展与三席协同控制台实施计划

> - 文档状态：已确认，作为后续产品设计与开发基线
> - 确认日期：2026-07-27
> - 适用范围：机构赛事平台、赛事工作人员任务、小程序计分台、球员技术统计台、MC 现场台、平台运营后台
> - 当前小程序实现目录：`native-dist/`

## 一、产品定位与项目目标

赛小蜂篮球 PC 端的主产品是“赛训经营增长平台”，面向教培机构的机构身份配置、校区、学员、课程、教练、课消、经营数据和增长管理。赛事中心是后续接入的附加业务模块，不替代、不重构上述核心教培管理能力。

本计划定义赛事中心扩展及其三席协同控制台。赛事中心复用机构、校区、教练、学员和球队等主数据，负责赛事、赛程、现场执行、赛果和赛事数据；它不拥有教培机构的员工、课程、课消、薪酬或财务主流程。

| 层级 | 业务定位 | 主要内容 |
|---|---|---|
| 核心平台 | 赛训经营增长平台 | 机构身份、校区、学员、教练、课程、课消、经营与增长数据 |
| 附加模块 | 赛事中心 | 赛事、赛制、赛程、现场执行、赛果、球员赛事数据 |
| 现场工具 | 三席协同控制台 | 比赛主控、球员技术统计、MC 现场控制 |

赛事中心可按机构需要启用；未启用赛事中心的机构仍可完整使用教培经营平台。

本计划优先完成以下业务闭环：

```text
机构创建赛事
→ 配置赛制与赛程
→ 分配馆内教练承担现场工作
→ 教练接受任务并完成到场确认
→ 选择一人 / 二人 / 三人记录模式
→ 现场协同计分、球员统计和 MC 控场
→ 现场执行教练提交赛果
→ 机构复核并生成报表
→ 平台监控赛事执行和异常
```

核心产品原则：

1. 保留现有单人控制台的操作方式和现场可用性。
2. 多人模式不是重新开发三套比赛系统，而是从原版主控台逐步拆出球员统计和 MC 权限。
3. 球队总比分、球员统计和 MC 行为共享同一场比赛、同一事件流。
4. 权限必须由服务端校验，不能只依赖前端隐藏按钮。
5. 比赛现场允许断网降级、重新连接、角色接管和完整审计。
6. 比分、计时等关键操作优先保证低延迟和可恢复，视觉效果不能阻碍操作。

## 二、产品边界

### 2.1 本计划包含

- 机构账号、校区、赛事工作人员和角色权限。
- 基于机构教练和外请裁判的赛事工作人员任务。
- 基础和复杂赛事创建、赛制、分组、赛程与场地编排。
- 一人、二人、三人现场记录模式。
- 比赛主控台。
- 球员技术统计台。
- MC 现场台。
- 多设备比赛房间、扫码加入、实时同步和操作审计。
- 赛果复核、球员技术统计、赛后赛事报告和赛事报表。
- 服务号的外请裁判邀请、身份绑定、任务数据查看和小程序任务入口。
- 平台方的机构、权益、赛事运行和异常监控。

### 2.2 首期不包含

- 通过手机麦克风直接完成现场扩声或专业混音。
- 与专业 24 秒硬件、电子大屏、计时器的硬件协议连接。
- 摄像头自动识别进球和球员。
- AI 自动生成全部技术统计。
- 教务课消、教练工资、财务会计等完整经营模块。
- 未经人工复核直接发布正式争议赛果。

上述能力可以在三席协同和赛事数据底座稳定后继续扩展。

## 三、三种现场记录模式

### 3.1 模式定义

| 模式 | 比赛主控员 | 球员技术统计员 | MC |
|---|---|---|---|
| 一人模式 | 操作原版完整控制界面，负责全部功能 | 无 | 无 |
| 二人模式 | 负责比分、计时、节次、犯规、暂停、24/14 秒和 MC | 独立记录球员技术统计 | 由主控兼任 |
| 三人模式 | 负责比分、计时、节次、犯规、暂停和 24/14 秒 | 独立记录球员技术统计 | 独立负责音乐、音效和喊麦辅助 |

### 3.2 固定规则

- 一人模式默认使用现有计分台布局和操作习惯。
- 二人模式首先拆出“球员技术统计台”。
- 三人模式在二人模式基础上继续拆出“MC 现场台”。
- 主控员始终拥有比赛开始、暂停、结束、比分修正、协作人员管理和最终赛果确认权限。
- 被拆出的功能在主控台中隐藏或变成只读，避免两台设备重复操作。
- 主控员保留紧急接管球员统计和 MC 的能力。
- 比赛中允许从一人模式升级到二人或三人模式，也允许在协作设备退出后降级。
- 模式变化只调整权限，不创建新的比赛记录，不复制比赛数据。

### 3.3 赛前选择流程

1. 主控员进入待执行比赛。
2. 系统检查双方球队、名单、赛事工作人员到场确认和比赛规则。
3. 主控员选择“一人控制 / 二人协作 / 三人协作”。
4. 一人模式直接进入原版计分台。
5. 二人模式生成“球员技术统计员”角色二维码。
6. 三人模式同时生成“球员技术统计员”和“MC”角色二维码。
7. 协作人员登录后扫码，确认加入本场比赛。
8. 主控员确认人员和设备在线后开始比赛。

机构赛事管理员也可以在 PC 后台预先分配角色。已分配人员从“我的赛事任务”直接进入对应控制台，不必再次扫码。

## 四、三席职责与权限

### 4.1 比赛主控台

比赛主控台负责“比赛发生了什么”，并拥有球队级比赛数据的最终控制权。

主要功能：

- 主客队 `+1 / +2 / +3` 和比分修正。
- 比赛时钟开始、暂停、重置。
- 节次切换、结束本节和结束比赛。
- 24 秒、14 秒、暂停和手动修正。
- 球队犯规、暂停次数和换人。
- 比赛场地左右显示交换，但不改变真实球队 ID 和历史事件归属。
- 最近操作、撤销和事件更正。
- 协作人员在线状态、权限分配、回收和接管。
- 最终比分确认和赛果锁定。

权威规则：

- 球队总比分只能由主控台的正式比分事件改变。
- 球员统计员不能直接修改球队总比分。
- MC 不能修改任何比分、计时和球员数据。
- 结束比赛、重开比赛、删除事件和修改最终赛果属于高风险操作，必须二次确认并写入审计记录。

### 4.2 球员技术统计台

球员技术统计台负责“球队事件属于哪个球员，以及该球员完成了什么技术动作”。

#### 基础统计

- 得分。
- 两分命中 / 未中。
- 三分命中 / 未中。
- 罚球命中 / 未中。
- 进攻篮板、 防守篮板、总篮板。
- 助攻。
- 抢断。
- 盖帽。
- 失误。
- 个人犯规。
- 技术犯规、违体犯规等扩展犯规类型。
- 上场、下场和上场时间。

#### 自动计算

- `FGM = 2PM + 3PM`
- `FGA = 2PA + 3PA`
- `FG% = FGM / FGA`
- `2P% = 2PM / 2PA`
- `3P% = 3PM / 3PA`
- `FT% = FTM / FTA`
- `REB = OREB + DREB`
- `PTS = 2PM × 2 + 3PM × 3 + FTM`

分母为 0 时显示 `—`，不显示错误百分比。

#### 页面结构

球员技术统计台包含三个页签：

1. `快速记录`：选择球员后使用大按钮记录命中、未中、篮板、助攻等。
2. `球员数据`：实时查看双方球员技术统计表。
3. `待处理`：处理未关联得分、未关联犯规、同步失败和数据差额。

二人模式下，主控台不再承担阵容与球员数据操作；主客队名单、场上阵容、换人状态、个人犯规和球员技术统计统一迁入球员技术统计台。主控仅保留队伍级比赛控制，避免两人同时在同一阵容界面操作。

顶部固定只读展示：

- 主客队与比分。
- 当前节次和比赛时间。
- 比赛状态。
- 网络与同步状态。
- 当前操作人员和授权范围。

比分和时间来自主控写入的统一比赛事件流与状态快照：主控每次更新比分、时钟或节次后，统计台按事件序号实时同步。统计台只展示，不拥有计时或比分写权限；发生序号缺口时先自动补齐，再继续提交球员数据。

#### 得分协作规则

主控员点击“主队 +2”后：

1. 系统立即生成球队得分事件并改变球队比分。
2. 球员技术统计台收到“主队 +2，待关联球员”。
3. 统计员选择具体球员。
4. 系统在原得分事件上补充球员、投篮类型和可选助攻球员。
5. 球员得分增加，但球队比分不再次增加。

投篮未中不会改变球队比分，由统计员独立记录投篮尝试。

罚球按每次出手记录命中或未中；命中罚球必须与主控台的 `+1` 事件关联。

#### 犯规协作规则

主控台记录球队犯规后，技术统计台选择具体犯规球员和犯规类型。系统同时维护球队本节犯规和球员个人犯规。

达到赛事设定的个人犯规次数时，主控台和技术统计台同时显示预警。

#### 数据核对

比赛过程中持续检查：

- 球队总比分是否等于全部球员得分之和。
- 球队犯规是否存在未关联球员的记录。
- 是否存在得分未关联、犯规未关联或统计同步失败。
- 球员得分是否满足投篮命中计算公式。

比赛结束时允许将无法确认的得分标记为“球队得分”，但必须记录确认人和原因。

### 4.3 MC 现场台

MC 现场台负责“现场听到什么、何时播放、MC 现在应该播报什么”，不参与比赛数据修改。

#### 只读比赛信息

- 当前比分、时间、节次和比赛状态。
- 最近得分球队和得分球员。
- 犯规球员、暂停、换人和关键比赛事件。
- 当前场上阵容。
- 下一场比赛及现场流程提示。

#### 音频控制

- 两分、三分和罚球音效。
- 进攻、防守音效。
- 暂停、换人和犯规提示。
- 欢呼、掌声和蜂鸣器。
- 开场、中场、结束和 MVP 音乐。
- 自定义音效与快捷位。
- 当前播放、暂停、继续、音量和进度。
- 一键停止全部声音。
- 一键降低背景音乐。

#### 喊麦辅助

系统根据比赛事件生成可读提示：

- 得分球员及得分类型。
- 球队暂停。
- 球队犯规累计。
- 球员犯规预警。
- 最后一分钟提醒。
- 首发阵容介绍。
- 中场、赛后和 MVP 播报。

MC 使用实体话筒完成现场喊麦。首期小程序负责提示词、音乐和音效，不直接承担麦克风采集与扩声。

#### 话筒模式

点击“话筒模式”后：

- 背景音乐自动降低或淡出。
- 非必要音效停止。
- 当前播报提示词放大。
- 结束话筒模式后按配置恢复背景音乐。

#### 事件推荐

比分、犯规和暂停事件可以向 MC 推荐合适音效，但默认由 MC 人工确认播放。自动播放必须作为独立配置开关，避免现场误播。

三人模式下，主控在阵容与球员数据拆至统计台后，底部原 MC 区域仅作为状态位：当第三台设备加入 MC 席，该区域整体锁定并置灰，显示“MC 已由其他设备接管”，不响应常规播放操作。第三台设备独立展示完整 MC 现场台；主控只在紧急情况下通过二次确认执行“停止全部音频”或“接管 MC”。

## 五、比赛房间与角色加入

### 5.1 比赛房间

每一场进行中的比赛建立唯一协同房间。房间包含：

- 比赛 ID、机构 ID 和赛事 ID。
- 当前模式。
- 当前主控员。
- 球员技术统计员。
- MC。
- 在线设备。
- 权限版本。
- 比赛状态快照。
- 最新事件序号。
- 角色接管记录。

### 5.2 扫码授权

二维码包含短时、单次有效的邀请凭证，只用于加入指定比赛和指定角色。

扫码流程必须满足：

- 用户先完成登录和身份校验。
- 邀请凭证带有比赛、角色、过期时间和一次性随机值。
- 服务端验证机构、比赛、角色空位和邀请有效性。
- 加入后生成正式比赛任务授权。
- 二维码截图重复使用不能获得第二次授权。
- 主控员可立即回收权限。

### 5.3 预分配

机构 PC 后台支持提前安排：

- 比赛主控教练。
- 球员技术统计员。
- MC。
- 后续扩展的记录员、计时员和 24 秒操作员。

任务状态：

```text
待指派
→ 待接受
→ 已接受
→ 已签到
→ 执行中
→ 待确认
→ 已完成
```

异常状态包括拒绝、改派、迟到、缺席、取消和比赛延期。

## 六、实时数据与事件模型

### 6.1 统一事件流

所有现场操作写入追加式比赛事件流。每个事件至少包含：

- `eventId`：全局唯一事件 ID。
- `matchId`：比赛 ID。
- `sessionId`：协同房间 ID。
- `orgId`：机构 ID。
- `sequence`：服务端递增序号。
- `eventType`：事件类型。
- `teamId`、`playerId`：关联球队和球员。
- `operatorId`：操作人员。
- `role`：操作时角色。
- `deviceId`：操作设备。
- `clientTime`、`serverTime`：客户端与服务端时间。
- `period`、`gameClockMs`、`shotClockMs`：比赛上下文。
- `payload`：事件数据。
- `permissionVersion`：操作时权限版本。
- `status`：有效、撤销、更正或待同步。
- `idempotencyKey`：重复提交防护。

### 6.2 事件分类

比赛主控事件：

- 比分增加、减少和修正。
- 比赛时钟开始、暂停和修正。
- 24/14 秒开始、暂停和复位。
- 节次切换。
- 球队犯规、暂停和换人。
- 比赛开始、结束、重开和锁定。

球员统计事件：

- 得分归属。
- 投篮命中和未中。
- 罚球命中和未中。
- 篮板、助攻、抢断、盖帽、失误。
- 个人犯规关联。
- 上下场和上场时间。

MC 事件：

- 音频播放、暂停、停止。
- 音量变化。
- 话筒模式开启和结束。
- 推荐音效采纳或忽略。

MC 事件保留现场执行记录，但不参与比分和技术统计计算。

### 6.3 快照

为了避免每次打开页面都重放全部历史事件，系统保存：

- 比赛状态快照。
- 球队技术统计快照。
- 球员技术统计快照。
- 最新已应用事件序号。

事件流是审计依据，快照是读取和恢复加速层。快照损坏时可以从事件流重建。

### 6.4 时钟同步

比赛时钟和 24 秒时钟不按每一秒写数据库，而是保存：

- 剩余毫秒数。
- 是否运行。
- 最近一次启动或暂停的服务端时间。
- 当前控制设备和控制权租约。

其他设备使用同一时间锚点本地计算显示值。一个时钟同一时间只能有一个控制设备。

## 七、同步、冲突与断网策略

### 7.1 正常同步目标

- 关键按钮点击后本机立即反馈。
- 正常网络下服务端确认目标不高于 500ms。
- 其他协作设备在 1 秒内看到新事件。
- 已缓存音效点击后目标在 150ms 内开始播放。
- 网络恢复后目标在 5 秒内完成自动重连。

以上为产品目标，最终以真机和真实场馆网络测试结果为准。

### 7.2 重复提交

- 每次操作生成唯一 `idempotencyKey`。
- 服务端重复收到同一操作时只应用一次。
- 页面明确显示“正在同步 / 已同步 / 同步失败”。
- 不能因为用户连续点击、网络重试或页面重进而重复加分。

### 7.3 冲突处理

- 主控台是球队比分和比赛状态的权威写入端。
- 球员统计只能关联和补充主控比分事件。
- MC 只订阅比赛事件并写入独立音频操作日志。
- 两名人员修改同一统计事件时，不静默覆盖，进入冲突提示。
- 撤销事件采用反向事件或状态标记，不直接删除历史记录。

### 7.4 断网降级

一人模式：

- 保持当前本地可用能力。
- 操作进入本地队列，联网后按事件 ID 补传。

多人模式：

- 主控设备断网时允许继续关键计分和计时，并明显显示离线状态。
- 球员技术统计台可以暂存未中、篮板等独立事件；得分归属在恢复连接后核对。
- MC 本地音频播放不依赖实时云端，但比赛事件提示可能暂停更新。
- 辅助设备不能在失去权限确认后修改球队总比分。
- 恢复连接后按事件序号、权限版本和幂等键进行合并。

### 7.5 角色掉线与接管

- 主控台持续显示三席在线状态。
- 协作设备掉线后，主控员收到提示。
- 主控员可以接管球员统计或 MC。
- 新设备扫码接管时，旧设备权限立即失效。
- 角色变更写入审计日志。

## 九、机构赛事平台配套能力

赛事中心作为赛训经营增长平台的附加模块，由机构 PC 后台提供比赛任务和赛事数据；其主数据依赖核心平台，但赛事模块保持独立的业务边界。

机构端首期页面：

1. 赛事运营工作台。
2. 赛事创建与规则配置。
3. 球队、球员和参赛名单。
4. 分组和赛程编排。
5. 场地和三席工作人员安排。
6. 现场执行监控。
7. 赛果与球员数据复核。
8. 报表、积分榜和导出。
9. 赛事工作人员安排：内部教练与外请裁判。
10. 员工账号、角色和操作记录。

复杂赛制首批支持：

- 单循环。
- 双循环。
- 小组循环 + 单败淘汰。
- 单败淘汰。

随后扩展交叉排位、名次赛、双败淘汰和系列赛。

赛程编排至少校验：

- 同球队时间冲突。
- 球队最短休息时间。
- 场地冲突。
- 教练与赛事工作人员冲突。
- 名单和资格未完成。
- 赛程发布后的版本变更。

## 十、服务号与平台后台

### 10.1 服务号与双通道工作人员

内部教练与外请裁判使用不同的任务进入方式：

| 人员来源 | 身份来源 | 任务分配 | 服务号能力 | 现场操作 |
|---|---|---|---|---|
| 馆内教练 | 核心平台的教练账号 | 机构赛事管理员在 PC 后台直接分配 | 可接收提醒 | 从个人小程序“我的赛事任务”进入对应控制台 |
| 外请裁判 | 服务号关注后绑定的轻量执行身份 | 机构赛事管理员创建外请邀请 | 查看执法比赛的任务、赛程、对阵、规则和相关数据 | 获得本场受限权限后进入小程序控制台 |

外请裁判不录入机构教练库，不进入课程、课消、薪酬或经营数据。其身份只绑定到受邀机构和被指派比赛，权限范围由 `matchStaffAssignments` 控制。

服务号承担：

- 外请裁判邀请、关注和身份绑定。
- 新任务、接受、拒绝、改派和到场确认通知。
- 时间、场地、对阵和规则变更通知。
- 执法比赛相关数据查看。
- 待确认赛果和赛后赛事报告通知。
- 服务号菜单进入“我的执法比赛”。

比赛中的高频计分、球员统计和 MC 操作仍统一由小程序控制台承担；服务号是邀请、通知和数据查看入口。

具体账号关联和消息能力在实施前依据届时微信官方规则复核。

### 10.2 平台运营后台

平台端首期管理：

- 机构开通、停用、套餐和配额。
- 机构管理员和账号状态。
- 赛事、比赛和三席使用情况。
- 同步失败、长时间离线和赛果异常。
- 赛事工作人员任务执行情况。
- 订单、权益和兑换码。
- MC 公共音频库。
- 用户反馈和客服处理。
- 平台操作审计。

平台人员协助机构修改业务数据时，必须填写原因并保留完整记录。

### M1：云端比赛房间与一人模式兼容

目标：先把原版单人计分台接入统一比赛房间和事件流，界面与操作习惯基本不变。

任务：

- 创建比赛房间。
- 统一比赛事件写入、幂等和序号。

- 完成比分、计时、犯规、暂停、换人和结束比赛事件。

验收：

- 原版单人模式核心功能没有回退。
- 连续点击和网络重试不会重复加分。
- 退出后重新进入可恢复比赛。
- 事件流可以重建最终比分。
- 现有赛果和赛后报告仍可生成。

### M2：二人模式与球员技术统计台

目标：从主控台拆出完整球员技术统计。

任务：

- 创建球员技术统计员角色。
- 实现角色二维码和预分配入口。
- 升级 `stats-scorer` 页面。
- 实现得分待关联队列。
- 实现命中、未中、篮板、助攻、抢断、盖帽、失误和犯规。
- 实现命中率和球员数据实时聚合。
- 将主客队名单、场上阵容与换人状态从主控拆至独立统计台，并固定展示同步的比分、比赛时间、节次和 24/14 秒。
- 实现球队比分与球员得分核对。
- 实现本人事件撤销和主控接管。

验收场景：

```text
主控员点击主队 +2
→ 技术统计员收到待关联事件
→ 选择 8 号球员
→ 记录一次两分命中
→ 再记录一次两分未中
→ 球员数据显示两分 1/2、得分 2
→ 球队比分只增加 2 分
```

附加验收：

- 技术统计员无法修改球队总比分和比赛时间。
- 比赛结束前能发现并处理未关联得分。
- 技术统计设备掉线后主控可接管。

### M3：三人模式与 MC 现场台

目标：从主控台继续拆出 MC，形成三席协同。

任务：

- 创建 MC 角色。
- 升级 `mc-system` 页面。
- 实现比赛事件实时订阅。
- 实现音效分类、播放队列、当前播放和一键停止。
- 实现话筒模式和背景音乐自动降低。
- 实现动态喊麦提示词。
- 实现推荐音效人工确认。
- 实现音频预缓存和离线播放。
- 实现主控底部 MC 区域的接管状态、锁定置灰和提示。
- 实现主控紧急停止和接管。

验收场景：

```text
主控员点击客队 +3
→ MC 台出现三分音效推荐
→ 技术统计员关联客队 11 号
→ MC 台更新“11 号球员三分命中”提示词
→ MC 播放音效并持话筒播报
→ 比分和球员数据不受 MC 操作影响
```

### M4：机构后台与赛事工作人员任务闭环

目标：由机构 PC 后台创建比赛并安排三席人员。

任务：

- 服务号外请绑定、执法比赛数据查看和小程序任务入口。
- 现场执行状态监控。
- 赛果待复核、锁定和更正申请。

验收：

- 机构只能查看和操作本机构数据。
- 工作人员能从“我的任务”进入正确控制台。
- PC 能看到三席在线、比赛状态和同步异常。
- 比赛结束后机构可以复核赛果和操作记录。

### M5：复杂赛事与赛程引擎

目标：由机构端完成复杂赛事和赛制配置。

任务：

- 单循环、双循环、单败淘汰和小组循环 + 淘汰赛。
- 分组、晋级和同积分排名规则。
- 场地、比赛时间和工作人员冲突检查。
- 赛程生成、人工调整、版本发布和变更通知。

验收：

- 能完整创建一项包含小组赛和淘汰赛的赛事。
- 赛程发布后小程序可读取比赛任务。
- 赛果确认后自动推进积分榜和下一轮对阵。
- 赛程变更保留版本和通知记录。

### M6：平台运营、试点与正式发布

目标：平台方可运营机构，真实赛事可稳定执行。

任务：

- 机构、套餐、权益和使用配额。
- 赛事运行和同步异常监控。
- 服务号通知完整接入。
- 日志、告警、备份和恢复。
- 真机、弱网、多人和长时间比赛测试。
- 一家真实机构、一项真实赛事试点。

试点最低规模：

- 1 家机构。
- 1 项赛事。
- 不少于 4 支球队。
- 不少于 10 场比赛。
- 至少覆盖一人、二人和三人模式各 1 场。
