## 四、开发注意事项

### 1. 域名、URL 与结构化数据

- 所有公开页面的 canonical、Open Graph URL、JSON-LD 实体 URL、Sitemap URL、robots Sitemap 声明和 llms 资源链接必须统一为 `https://www.sxfbasketball.cn/`。
- 主页只能使用 `https://www.sxfbasketball.cn/` 作为唯一标准页；`http://sxfbasketball.cn/` 与 `https://www.sxfbasketball.cn/index.html` 仍需配置 301 收敛到 HTTPS 根路径，避免重复入口。
- 页面新增、改名、删除时必须同步维护：文章中心、Sitemap、llms.txt、首页/文章内链和 canonical。
- 结构化数据必须与页面可见内容一致；FAQ 数量、产品功能、品牌名称和 URL 不得出现“代码写了、页面没有”的情况。

### 2. 内容与产品口径

- 品牌中文名称统一为“赛小蜂篮球”，可用简称“赛小蜂”。
- 官网当前产品定位为“机构训赛经营增长平台”，公开表达应聚焦赛事、计分、球队/球员基础资料、赛果留存、现场 MC 等已具备或已明确开放的能力。
- 教务、经营数据、付费、支付、家长传播等未正式开放或仍在规划的能力，不能写成已上线功能。
- 官网不公开价格、套餐金额或未确认的商业承诺；不得重新加入价格类结构化数据。
- 文章应优先解决一个清晰、可搜索、可执行的问题，避免相同关键词堆叠和同意图重复。
- 每篇文章保留自然语境的首页内链、相关内容内链、备案信息与独立 title/description/canonical/JSON-LD。

### 3. AEO/GEO 与收录证据边界

- HTTP 200、进入 Sitemap、出现在内容中心、出现在 llms.txt，只能证明页面可访问或已部署，不能证明已发现或已收录。
- 只有站长平台的 URL 检查、索引数据或可核验的搜索结果，才能标记为“已收录”。
- 内容台账必须区分：本地草稿、已上线、已发现、已收录、未收录、待复查。
- 外链仅做可控品牌入口、真实合作、可引用资源与人工投稿规划；自动化不得注册外部账号、购买链接、代发内容或修改第三方页面。

### 4. 静态站点与部署安全

- 站点代码主要位于根目录 `index.html`、`articles/`、`guides/`、`website-assets/`、`robots.txt`、`sitemap.xml`、`llms.txt` 与 `BingSiteAuth.xml`。
- `tools/deploy-seo-site.ps1` 只能上传白名单静态文件和目录；不得将整个仓库、`native-dist/`、云函数、数据库备份、环境变量、密钥或本地配置上传到静态托管。
- 部署必须通过 `tools/sxf-cloud.ps1 basketball` 路由到篮球环境 `sxf-basketball-d9gp6yt0rd1f7be4d`，不依赖全局 `tcb login`，不得手动覆盖环境 ID。
- 部署前必须执行 `npm run site:validate`；部署后应回读正式域名和 CloudBase 访问入口的首页、内容中心、Sitemap、robots、llms 及新增文章。
- 所有面向用户的中文文件使用 UTF-8 无 BOM；若终端显示乱码，应先核验文件真实字节，不能直接以终端乱码覆盖源文件。

### 5. 页面、资源与体验

- 首页和文章页保持移动端、桌面端可读，正文链接应有可识别样式、悬停与键盘焦点状态。
- Logo、主视觉和文章样式从共享 `website-assets/` 使用；不应从原型截图裁切文字或 UI 作为生产素材。
- 新增图片需确认来源、授权、压缩体积与替代文本；本地图片不会自动写入飞书或外部 CMS。
- 备案信息、品牌名称、产品描述与联系入口属于全站一致性信息，任何一处变更都要全站检索并同步。

### 6. 协作与版本边界

- 工作区可能同时有后台、小程序、官网和内容任务的未提交改动；官网任务只修改其范围内文件，不回滚、不混入无关改动。
- 本地验证、文档记录、部署、Git 提交和推送是不同动作。未获得明确授权时，不推送 GitHub/Gitee，不部署，不提交站长平台。
- 每次官网批次应更新内容/收录台账和当日开发日志，至少记录：新增 URL、校验结果、部署结果、线上回读、收录证据、未解决问题与下一次复查时间。

## 五、建议的下一阶段顺序

1. 修复 `robots.txt`、`llms.txt` 和备案信息，确保所有公开域名、Sitemap 与品牌资料一致。
2. 重新执行 `npm run site:validate`，通过后再进行部署；部署后回读关键入口和全部新增 URL。
3. 在百度与 Bing 站长平台回读首页、Sitemap 状态、发现 URL、抓取与索引数据，更新台账，不用推测填补数据空白。
4. 处理 HTTP 与 `/index.html` 到唯一 HTTPS 首页的 301 收敛。
5. 按“核心主题 + 单一问题 + 具体场景”继续内容更新，同时做人工审核，避免关键词重复和产品能力夸大。
6. 按外链台账推进真实、可验证的品牌入口与合作提及；保留公开 URL、锚文本、日期和失效检查结果。
