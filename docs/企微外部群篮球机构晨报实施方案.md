# 企微外部群篮球机构晨报实施方案

> 状态：已确认实施  
> 确认日期：2026-08-25  
> 适用对象：赛小蜂篮球运营团队、篮球培训机构客户群群主  
> 关联任务：GitHub Issue #8

## 一、交付目标

每天早上由固定 IP 服务器完成篮球资讯采集、事实核验、机构视角改写和内容校验，然后通过企业微信自建应用创建一条外部客户群群发任务。群主在企业微信中核对并点击一次发送，服务随后查询发送结果并记录状态。

每天只生成一份晨报，基本结构固定为：

- 国内篮球短讯1—2条、国外篮球短讯1—2条；
- 1 条面向篮球培训机构的观察；
- 1 段独立于新闻的机构提醒，按开学、续费、排课、教练交接等运营节点轮换；群内不展示“今天可做”；
- 可追溯的资料来源。

目标读者是篮球培训机构的创始人、校长、教务负责人和教练负责人。晨报帮助他们判断招生、续费、课程、教练管理和赛事运营问题，不承担产品推广任务。

## 二、企微能力边界

本方案使用官方开放接口，不使用客户端 Hook、模拟点击或其他非官方自动化。

外部客户群不能由自建应用无人值守直发。`externalcontact/add_msg_template` 只负责创建群发任务，成员或群主仍须在企业微信客户端确认发送。固定 IP 的作用是配置企业可信 IP、稳定调用接口和承载定时任务，不能绕过群主确认。

已确认的官方链路如下：

1. 自建应用取得 `access_token`；
2. 服务调用 `externalcontact/add_msg_template`，使用 `chat_type: "group"` 创建客户群群发任务；
3. 企业微信向对应群主展示待发送任务；
4. 群主一键确认；
5. 服务调用 `externalcontact/get_groupmsg_task` 查询成员任务状态；
6. 对仍未确认的任务，在频控允许范围内调用 `externalcontact/remind_groupmsg_send` 提醒；
7. 服务记录已发送、待确认、部分失败或需要人工处理的结果。

当传入 `chat_id_list` 时，可预先指定最多 2000 个客户群；群主无需再次挑选群，但仍要确认发送。该能力要求相关企业微信客户端版本不低于 4.1.10。`allow_select` 默认保持 `false`，避免群主临时改变目标群范围；确需允许重选时再由运营负责人修改配置。

主要官方文档：

- [创建企业群发](https://developer.work.weixin.qq.com/document/path/92135)
- [提醒成员群发](https://developer.work.weixin.qq.com/document/path/97610)
- [获取群发成员发送任务列表](https://developer.work.weixin.qq.com/document/path/93338)

## 三、部署结构

服务独立部署在现有固定 IP 服务器，不与小程序云函数、企微客户路由或企微文档助手共用进程。

| 项目 | 建议值 |
|---|---|
| 仓库源码 | `cloudfunctions/sxWecomGroupBriefing/` |
| 服务器源码 | `/opt/sxf-platform/apps/wecom-group-briefing` |
| 环境配置 | `/opt/sxf-platform/config/wecom-group-briefing.env` |
| 幂等与任务状态 | `/opt/sxf-platform/data/wecom-group-briefing/` |
| 本机健康检查 | `127.0.0.1:3400/health` |
| 时区 | `Asia/Shanghai` |

晨报只需要主动访问资讯源和企微接口，第一阶段不开放公网业务入口，也不新增 Nginx 路由。健康检查端口只绑定本机。以后若增加人工预览、改稿或补发入口，必须使用独立鉴权并限定精确路径。

当前幂等锁和状态文件按单进程设计，生产部署只能运行一个服务实例。不得用多副本、双机同时挂载同一状态目录或并行启动两个调度进程；以后需要扩容时，先把创建锁迁移为数据库条件更新或分布式锁。

生产环境文件使用以下配置名，只填写到服务器，不在仓库保存真实值：

| 配置 | 用途 |
|---|---|
| `SERVICE_ENABLED` | 服务总开关，验收前保持 `false` |
| `SCHEDULER_ENABLED` | 每日调度开关 |
| `AUTO_CREATE_ENABLED` | 内容通过校验后自动创建企微待发任务 |
| `AUTO_REMIND_ENABLED` | 到达提醒时间后自动检查并提醒未发送群主 |
| `ADMIN_TOKEN` | 本机管理页 Basic Auth 密码 |
| `OPENAI_API_KEY`、`OPENAI_MODEL` | 通过 Responses API 和网页搜索生成结构化晨报 |
| `SOURCE_DOMAIN_ALLOWLIST` | 可进入引用流程的来源域名 |
| `REQUIRE_SEARCH_PROVENANCE` | 生产环境保持 `true`，要求每个引用链接确实来自当次网页搜索 |
| `BRIEF_LOOKBACK_HOURS` | 优先24小时，不足3条时最多回看72小时 |
| `NEWS_DEDUP_DAYS` | 新闻事件跨日去重窗口，默认7天 |
| `WECOM_CORP_ID`、`WECOM_CONTACT_SECRET` | 企微企业与客户联系接口凭据 |
| `WECOM_TIMEOUT_MS` | 企微接口超时时间，防止请求长期占用任务锁 |
| `WECOM_SENDER_USERID` | 明确的群主或发送成员 userid |
| `WECOM_CHAT_ID_LIST` | 明确的外部客户群 chatid 列表 |
| `SCHEDULE_HOUR`、`SCHEDULE_MINUTE` | 晨报准备时间，默认 09:00 |
| `REMINDER_HOUR`、`REMINDER_MINUTE` | 待确认任务检查与提醒时间 |
| `REMINDER_MIN_INTERVAL_MINUTES` | 两次提醒的最小间隔，默认 60 分钟 |
| `DATA_DIR`、`STATE_FILE` | 持久化幂等、任务和提醒状态 |
| `PORT` | 本机管理与健康检查端口，默认 3400 |

这些开关默认应采用保守值。先打开服务和手工预览，完成测试群验收后，再依次启用调度、自动创建和自动提醒。

## 四、每日运行流程

### 4.1 调度

默认每天 09:00（北京时间）准备并创建任务。调度必须同时具备：

- 每日日期幂等；
- 进程重启后的当日补偿；
- 单进程互斥，避免定时器和补偿任务同时运行；
- 明确失败重试，不能用高频固定轮询代替日调度。

实际发布时间取决于群主确认时间。对外不得承诺“09:00 自动发进群”，应表述为“09:00 生成待发送晨报，群主确认后发进群”。

### 4.2 采集与筛选

1. 通过 Responses API 的网页搜索从配置的 HTTPS 来源白名单读取近期内容；
2. 先保留原始标题、发布时间、来源名称、原文链接和可核验事实；
3. 合并同一事件的重复报道；
4. 按读者相关性选出固定3条赛讯；
5. 机构提醒不从新闻推导，按日期从项目确认的篮球培训运营节点中轮换；
6. 优先最近24小时；不足3条时可放宽到72小时，不用更早旧闻或无关热点凑数；
7. 按《企微外部群篮球机构晨报内容规则》生成最终文案。

来源白名单只接受 `https://`，禁止用户名密码 URL、IP 直连、非标准端口、本地地址和白名单域名的伪后缀。来源域名由部署配置维护；新增域名前需确认来源身份、稳定性和引用权限。

生产环境启用搜索来源追踪。最终晨报引用的每个 URL 必须出现在本次网页搜索工具返回的来源列表中；仅由模型文本生成、但没有搜索调用证据的链接一律转人工审核。

### 4.2.1 已知证据边界

当前来源追踪只能证明“引用 URL 出现在本次网页搜索结果中”，不能独立证明模型填写的 `published_at`、摘要、比分或机构观察与原页面逐字一致。系统现阶段属于“有来源约束的自动采编”，不能宣传为自动全文事实核验。

初次上线必须保持 `AUTO_CREATE_ENABLED=false`，由运营人员在管理页打开原文，核对发布日期、关键数字、赛事结果和观察依据。完成一段稳定的测试群运行后可以启用自动创建待发任务，但群主点击发送前的核对仍是最后一道事实关口。页面无法访问、发布日期看不清、来源与摘要不一致时，当天晨报不发送。

若以后要减少这一步人工核对，需要另行增加原页面抓取、发布时间提取和支持摘要的原文证据片段，并处理站点访问规则、版权和页面变化；本期不把网页搜索返回的 URL 等同于原文事实已核验。

### 4.3 发布前校验

创建企微任务前必须通过以下硬校验：

- 国内、国外新闻各1—2条，总数2—4条；
- 国内至少1条为职业联赛或国家队新闻，群众业余赛事最多1条；
- 恰好1条独立于新闻的机构提醒；后台可保留编辑记录，但群内不展示“今天可做”；
- 每条事实有来源和日期；
- 最近7天不得重复同一链接或高度相似的新闻事件；
- 每个链接通过 HTTPS 来源白名单；
- 正文以 UTF-8 计算不超过企微 `text.content` 的 4000 字节限制；
- 群发只使用精简文本，不附加来源链接卡片；来源留在后台核验记录中；
- 不含密钥、访问令牌、客户资料、未成年人隐私或后台调试信息；
- 不含未经证据支持的数字、因果结论和引语；
- 不含产品广告或变相销售话术。

建议将正文控制在 3600 字节以内，给日期、来源名称和必要修订留出余量。超限时优先删除重复解释，不能截断链接、数字或证据边界说明。

### 4.4 创建待发送任务

服务调用 `externalcontact/add_msg_template` 时至少提交：

- `chat_type: "group"`；
- `sender`：具有客户联系能力、在自建应用可见范围内的成员；
- 经校验的 `text.content`；
- 配置的 `chat_id_list`；
- `allow_select: false`；
- 不超过 9 个合规附件。

链接附件也按 UTF-8 字节校验：标题不超过 128 字节、描述不超过 512 字节，原文链接和封面链接不超过 2048 字节。不能用 JavaScript 字符数代替企微字节上限。

接口成功会返回 `msgid`，也可能同时返回 `fail_list`。服务必须保存 `msgid`、目标群集合、内容摘要、创建时间和失败群列表；不能把“拿到 msgid”写成“已经发送”。`fail_list` 表示部分目标群未创建成功，必须进入运营提示，不能静默忽略。

## 五、幂等与失败处理

企业微信创建群发任务接口没有业务幂等键，本地状态是防止重复任务的唯一屏障。

本地唯一键使用“北京时间日期 + sender + 排序后的目标群集合”。同一天、同一发送成员、同一目标群集合只能存在一个创建动作。内容修订不能自动生成第二个任务；已有任务需要替换时，必须由运营人员明确执行停止、重建流程。

创建前先持久化 `creating` 状态和请求摘要，成功后再写入 `msgid`。处理规则如下：

| 情况 | 自动动作 |
|---|---|
| 已保存 `msgid` | 返回既有任务，不再创建 |
| 明确的参数或权限错误 | 记录失败，停止重试并提示人工处理 |
| 网络超时、连接中断、响应无法解析 | 标记 `unknown`，禁止自动重建，先人工核对企微后台 |
| 查询返回 41063“正在派发” | 退避后重查，不创建新任务 |
| `access_token` 失效 | 刷新令牌后重放可安全查询；创建请求若结果未知则不重放 |
| 目标群部分失败 | 保存 `fail_list`，其余目标按既有 `msgid` 继续，不整单重建 |

任何 API 失败都不得把同一个晨报自动创建两次。

## 六、提醒与结果回读

服务内部状态分为两层，不能混用“任务创建成功”和“消息已经进群”：

| 层级 | 状态 | 含义 |
|---|---|---|
| 内容 | `ready` | 内容和来源校验通过，可以创建任务 |
| 内容 | `review_required` | 内容、来源或权限需要人工核对 |
| 创建 | `creating_task` | 已落幂等记录，正在调用企微 |
| 创建 | `task_created` | 取得 `msgid`，所有指定群均已进入待发任务 |
| 创建 | `task_created_partial` | 取得 `msgid`，但 `fail_list` 中有未成功目标群 |
| 创建 | `creation_uncertain` | 请求结果未知，禁止自动重建，等待人工对账 |
| 创建 | `create_failed` | 企微明确拒绝请求，需修正配置后人工处理 |
| 送达 | `pending` | 群主任务状态为未发送 |
| 送达 | `sent` | 群主已确认并发送 |
| 送达 | `unknown` / `not_pending` | 暂时无法确认或当前任务不处于待发送状态 |

查询 `get_groupmsg_task` 时，成员任务 `status: 0` 表示未发送，`status: 2` 表示已发送；只有已发送记录才有 `send_time`。客户群场景判断待确认应以任务状态为准，不能因为发送结果列表为空就判断任务不存在。

`create_failed` 不能由定时任务自行重试。运营人员查清错误码并修正权限或参数后，才可通过受鉴权保护的“重置被拒绝任务”操作把该记录恢复到可创建状态；每次重置都要保留原因和时间。`creation_uncertain` 不允许用这个入口重置，必须先在企微群发记录中完成对账。

提醒接口不是幂等动作。24 小时内每个群发任务最多提醒 3 次，服务必须保存每次提醒时间和结果。默认只在晨报仍待确认且达到配置的等待时间后提醒一次；后续提醒必须遵守最小间隔和上限。遇到 41094 频控时停止提醒，不循环重试。

企微对每个客户或客户群有接收频率限制。默认上限与当月天数相关，也可能由企业在群发助手中改为每周 7 条或每天 1 条。运营人员修改群发频率前，应先检查每日晨报是否仍能覆盖目标群。

## 七、权限与安全

自建应用需要被配置为“客户联系可调用接口的应用”，且发送成员位于应用可见范围内并具有客户联系能力。服务器固定公网 IP 加入企业可信 IP 后再启用生产任务。

以下值只通过服务器的 0600 环境文件或等价的密钥管理提供：

- 企业 ID；
- 自建应用 Secret；
- 应用 AgentId；
- 发送成员 userid；
- 目标客户群 chatid；
- 服务管理鉴权密钥；
- 内容源或模型所需的第三方密钥。

禁止读取、打印、写入仓库或返回这些密钥。日志只记录业务日期、本地幂等键摘要、`msgid` 的脱敏值、状态、企微错误码和请求耗时；不得记录 `access_token`、Secret、完整客户群名单或客户个人信息。

若以后开放手工触发接口，必须采用恒定时间比较验证管理令牌；缺失或错误令牌统一返回未授权，不在错误消息中泄露期望值。

## 八、上线步骤与验收

1. 在企微后台创建自建应用，并配置客户联系接口权限、应用可见范围和可信 IP；
2. 确认发送成员是目标客户群群主或具备相应群发资格；
3. 在服务器外置环境文件中配置成员和测试群，不写入仓库；
4. 运行本地契约测试：`node tools/test-wecom-group-briefing.js`；
5. 先以一个内部测试客户群执行单次创建；
6. 在企微客户端确认看到待发送任务，核对目标群和正文；
7. 群主点击发送；
8. 服务回读为已发送，并记录实际 `send_time`；
9. 验证同日重复触发返回原 `msgid`，不会再次创建；
10. 验证错误令牌无法触发、来源白名单拦截异常链接、超长正文不能进入企微；
11. 测试网络超时后状态进入 `unknown`，不会盲目重建；
12. 测试提醒只对待确认任务发送，且不会超过配置上限。

满足以上条件后，再把目标群从测试群切换为正式客户群。正式启用第一周每天由运营人员检查内容来源、目标群、待确认状态和发送回读；发现错误先停任务，不通过提高重试次数处理。

## 九、不在本期范围

- 绕过群主确认的外部群自动直发；
- 非官方客户端自动化、Hook 或模拟点击；
- 自动加入客户群、自动更换群主或自动扩大应用可见范围；
- 在未经人工核验的情况下批量补发历史晨报；
- 把晨报改成赛小蜂篮球产品广告；
- 使用客户聊天记录训练内容模型；
- 公开管理后台或向公网暴露健康检查端口。
