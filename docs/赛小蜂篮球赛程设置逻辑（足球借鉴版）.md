# 赛小蜂篮球赛程设置逻辑（足球借鉴版）

> 用途：把赛小蜂篮球赛事中心现有的“赛制生成、时间段配置、场次落位、冲突校验、手动调赛”逻辑整理为跨项目方案，供赛小蜂足球复用。
>
> 版本：V1.3｜整理日期：2026-08-30

## 一、先分清两套引擎

赛程不是一次性生成的单张表，而是两个相互独立、前后衔接的步骤：

1. **赛制引擎**决定有多少场、谁和谁比赛、胜负进入哪里，输出场序和依赖关系。
2. **排赛引擎**把每个场序安排到具体日期、开赛时间和场地，不能改变原来的对阵和晋级关系。

因此，只调整时间、球场或交换两场比赛时，场序不能变化；只有参赛规模、分组、赛制、出线人数或排位方式变化时，才需要重建对阵和场序。

## 二、篮球当前的赛程设置项

### 1. 赛事级设置

- 比赛开始日期、结束日期。
- 启用的场馆及球场。
- 上午、下午为默认必备时段，晚间时段可选。
- 篮球当前默认时段为：上午 `09:00—12:00`、下午 `14:00—18:00`；晚间开启后为 `19:00—21:30`。
- 日期范围按自然日计算并包含首尾两天。

### 2. 每片场地独立设置

每片场地分别保存：

- 是否启用；
- 适用组别；
- 场地形态，如标准全场、半场；
- 单场比赛时长；
- 两场之间的缓冲时间；
- 上午、下午和晚间的独立起止时间；
- 系统推算出的每日开赛时间。

篮球当前的年龄组默认建议为：

| 组别 | 比赛时长 | 缓冲 | 时隙间隔 |
| --- | ---: | ---: | ---: |
| U8、U10 | 40分钟 | 10分钟 | 50分钟 |
| U12及以上 | 50分钟 | 10分钟 | 60分钟 |

这些只是初始化建议，最终以赛事规程和场地设置为准。

### 3. 半场资源

篮球中，一片设置为“半场”的球场会拆成 `A半场`、`B半场` 两个可独立排赛的资源；标准全场只生成一个资源。足球可复用这一思想，把一片标准足球场拆成多个七人制或五人制小场，但必须增加“父场地互斥”规则，避免同一时间既使用整场，又使用其子场。

## 三、时间段与开赛时间生成

### 1. 基本公式

```text
时隙间隔 = 单场比赛时长 + 场间缓冲
```

系统从某一时间段的开始时间向后递推。只有当一场完整比赛能够在该时间段结束前完成时，才生成这个开赛时间：

```text
当前开赛时间 + 单场比赛时长 <= 本时段结束时间
```

生成当前开赛时间后，下一个开赛时间为：

```text
下一开赛时间 = 当前开赛时间 + 单场比赛时长 + 场间缓冲
```

缓冲用于决定下一场何时开始；最后一场比赛结束后不强制再留一段无比赛缓冲。

### 2. 示例

上午 `09:00—12:00`，比赛40分钟、缓冲10分钟时：

```text
09:00、09:50、10:40、11:30
```

`11:30` 开赛、`12:10` 才结束，因此实际上不能生成。合法时间为：

```text
09:00、09:50、10:40
```

### 3. 手动调整

- 管理员可以逐条新增、编辑或删除每日开赛时间。
- 修改某片场地的时段、比赛时长或缓冲后，应清空手动开赛时间并重新推算，防止遗留非法时间。
- 比赛不能跨越上午、下午或晚间的结束线；例如一场比赛从 `11:40` 开始但 `12:20` 才结束，应阻止保存并提示调整时段或移到下一时段。
- 日历页可为某一个比赛日临时增加时间行，但它属于日历操作，不应偷偷改写赛事的基础时间模板。

## 四、场次数量的生成逻辑

### 1. 小组单循环

一个小组有 `N` 支队时：

```text
小组场次 = N × (N - 1) ÷ 2
每队场次 = N - 1
```

例如4队一组为6场；两个4队小组共12场。

### 2. 全部球队单循环

公式同上。8队单循环共28场、7轮，每轮4场，任意两队只交锋一次。

### 3. 普通单败淘汰

```text
场次 = N - 1
```

如增加三、四名决赛，再加1场。非 `2` 的幂次参赛规模通过轮空签位处理，轮空不生成虚假比赛场次。

### 4. 单败淘汰全员排位

当 `N = 2^m` 时：

```text
场次 = N ÷ 2 × log2(N)
```

- 8队：12场；
- 16队：32场；
- 32队：80场。

每轮胜者进入较高名次线，负者进入较低名次线，直到每支队伍都有唯一名次。

### 5. 两组四队 + 淘汰赛 + 全员排位

- 小组赛：12场；
- 1—4名、5—8名交叉赛：4场；
- 冠亚军、三四名、五六名、七八名：4场；
- 合计：20场。

### 6. 小组赛 + 淘汰赛的完整排位原则

“小组赛 + 淘汰赛”不能只生成冠军线。若赛事选择“全员排位”，小组赛结束后必须按小组名次把全部球队分入不同名次线：

- 获得出线资格的球队进入高名次线，例如 `1—8名线`；
- 未获得冠军线出线资格的球队继续进入低名次线，例如 `9—16名线`；
- 每条名次线内部都采用交叉淘汰排位；
- 每轮胜者进入该名次线的较高半区，负者进入较低半区；
- 负者不能直接结束比赛，必须继续参加下一轮排位，直到每支球队得到唯一名次。

因此，“9—16名排位赛”不是一轮比赛，也不是普通单败淘汰。它是一棵完整的8队排位树：

```text
9—16名首轮交叉赛（4场）
├─ 4个胜者 -> 9—12名排位半决赛（2场）
│  ├─ 2个胜者 -> 9、10名排位赛（1场）
│  └─ 2个负者 -> 11、12名排位赛（1场）
└─ 4个负者 -> 13—16名排位半决赛（2场）
   ├─ 2个胜者 -> 13、14名排位赛（1场）
   └─ 2个负者 -> 15、16名排位赛（1场）
```

一条8队完整排位线共12场：

```text
首轮4场 + 第二轮4场 + 最终名次赛4场 = 12场
```

### 7. 16队、四组四队、每组前二出线的完整示例

假设16支球队分为A、B、C、D四组，每组4队，小组单循环后每组前2名进入 `1—8名线`，每组第3、第4名进入 `9—16名线`。

#### 第一阶段：小组赛

```text
每组场次 = 4 × 3 ÷ 2 = 6场
四组小组赛 = 6 × 4 = 24场
```

#### 第二阶段：1—8名线

首轮交叉对阵采用相邻组交叉，并避免同组球队立即相遇：

```text
场序25：A组第1 vs B组第2
场序26：C组第1 vs D组第2
场序27：B组第1 vs A组第2
场序28：D组第1 vs C组第2
```

首轮后必须同时生成 `1—4名线` 和 `5—8名线`：

```text
场序29：场序25胜者 vs 场序26胜者    1—4名半决赛
场序30：场序27胜者 vs 场序28胜者    1—4名半决赛
场序31：场序25负者 vs 场序26负者    5—8名排位半决赛
场序32：场序27负者 vs 场序28负者    5—8名排位半决赛

场序33：场序29胜者 vs 场序30胜者    决赛，决定第1、2名
场序34：场序29负者 vs 场序30负者    三、四名决赛
场序35：场序31胜者 vs 场序32胜者    5、6名排位赛
场序36：场序31负者 vs 场序32负者    7、8名排位赛
```

#### 第三阶段：9—16名线

未进入1—8名线的8支球队必须继续排位。首轮仍采用相邻组、相邻名次交叉：

```text
场序37：A组第3 vs B组第4
场序38：C组第3 vs D组第4
场序39：B组第3 vs A组第4
场序40：D组第3 vs C组第4
```

首轮胜者进入9—12名线，首轮负者进入13—16名线：

```text
场序41：场序37胜者 vs 场序38胜者    9—12名排位半决赛
场序42：场序39胜者 vs 场序40胜者    9—12名排位半决赛
场序43：场序37负者 vs 场序38负者    13—16名排位半决赛
场序44：场序39负者 vs 场序40负者    13—16名排位半决赛
```

第二轮后继续按胜负分流，生成四场最终名次赛：

```text
场序45：场序41胜者 vs 场序42胜者    9、10名排位赛
场序46：场序41负者 vs 场序42负者    11、12名排位赛
场序47：场序43胜者 vs 场序44胜者    13、14名排位赛
场序48：场序43负者 vs 场序44负者    15、16名排位赛
```

完整场次数量：

```text
小组赛24场 + 1—8名线12场 + 9—16名线12场 = 48场
```

此时16支球队均参加小组赛3场和排位赛3场，每支球队总计6场，并最终得到第1至第16的唯一名次。

### 8. 其他分组规模的套用方式

#### 8队：两组四队

小组赛后，A/B组前2名进入1—4名线，第3、第4名进入5—8名线：

```text
1—4名交叉：A1-B2、B1-A2
5—8名交叉：A3-B4、B3-A4
```

随后分别生成决赛、三四名、五六名和七八名排位赛。总计为小组赛12场 + 排位赛8场 = 20场。

#### 16队：两组八队、每组前四出线

同样拆成1—8名线和9—16名线，但首轮来源改为：

```text
1—8名线：A1-B4、B1-A4、A2-B3、B2-A3
9—16名线：A5-B8、B5-A8、A6-B7、B6-A7
```

后续胜负分流规则与上面的8队完整排位树完全相同。具体签位顺序可以由赛事规程调整，但必须同时满足：跨组交叉、同名次线球队数量正确、来源可追溯、胜负去向固定。

#### 通用算法

若某一条名次线包含 `K = 2^m` 支球队，该名次线决出全部唯一名次所需场数为：

```text
名次线场数 = K ÷ 2 × log2(K)
```

不能使用普通单败淘汰的 `K - 1` 场公式，因为普通单败只能确定冠军，不能确定该名次线内的全部顺序。

### 9. 必须区分“小组赛 + 淘汰赛”和“单败淘汰”

这两个赛制都可能出现1/8决赛、1/4决赛、半决赛和决赛，但球队来源、未进入冠军线球队的处理和总场数完全不同，产品中必须作为两个独立赛制保存。

| 对比项 | 小组赛 + 淘汰赛 | 单败淘汰 |
| --- | --- | --- |
| 淘汰前是否比赛 | 先进行小组循环赛 | 不进行小组赛 |
| 首轮球队来源 | 来自小组名次，如A组第1、B组第2 | 来自抽签签位或种子排位 |
| 是否存在“未出线球队” | 存在；未进入冠军线的球队可进入低名次排位线 | 不存在；所有球队从一开始就在淘汰签表中 |
| 普通模式 | 小组出线球队争冠，未出线球队结束或按规程另排 | 输一场即结束，直至决出冠军 |
| 全员排位模式 | 各小组名次分别进入1—8、9—16等名次线 | 每轮胜负分流，形成1—N名完整排位树 |
| 首轮对阵依据 | 小组名次交叉，优先避免同组立即重赛 | 种子保护、抽签签位和轮空规则 |
| 对阵来源文案 | `A组第1`、`B组第2` | 第一轮是真实球队，后续为`场序X胜者/负者` |

#### 小组赛 + 淘汰赛

系统必须先完成小组赛排名，再根据赛事配置把不同名次送入不同淘汰或排位线。以16队、四组四队、每组前2名出线为例：

```text
A/B/C/D组第1、第2 -> 1—8名线，共8队，第一轮是1/4决赛
A/B/C/D组第3、第4 -> 9—16名线，共8队，第一轮是9—16名交叉排位赛
```

这里赛事总数虽然是16队，但冠军线只有8队，所以冠军线第一轮必须叫 `1/4决赛`，不能叫 `1/8决赛`。

只有当小组赛后有16支球队全部进入同一条冠军淘汰线时，第一轮才叫 `1/8决赛`；此时也就不存在“未出线的9—16名球队”。轮次名称必须根据当前名次线的参赛队数计算：

```text
16队进入同一淘汰线 -> 1/8决赛
8队进入同一淘汰线  -> 1/4决赛
4队进入同一淘汰线  -> 半决赛
2队进入同一淘汰线  -> 决赛
```

若选择全员排位，不能在小组赛后只生成冠军线；所有未进入冠军线的球队必须按小组排名进入对应的低名次线，并继续比赛直到名次唯一。

#### 单败淘汰

单败淘汰没有小组积分和小组出线。赛事开始前直接按种子或抽签形成签位：

```text
第一轮：真实球队 vs 真实球队
第二轮起：场序X胜者 vs 场序Y胜者
```

普通单败淘汰中，负者结束比赛：

```text
N支球队普通单败场数 = N - 1
```

- 8队：1/4决赛4场 + 半决赛2场 + 决赛1场 = 7场；
- 16队：1/8决赛8场 + 1/4决赛4场 + 半决赛2场 + 决赛1场 = 15场；
- 如设置三、四名决赛，再增加1场。

单败淘汰也可以选择“全员排位”，但这已经不是“输一场结束”的普通单败，而是以单败签表为入口的胜负双向分流排位：

```text
首轮胜者 -> 较高名次线
首轮负者 -> 较低名次线
后续每轮继续按胜负分流
直到所有球队获得唯一名次
```

- 8队单淘全员排位：12场；
- 16队单淘全员排位：32场。

全员排位优先要求参赛队数为2的幂次（4、8、16、32）。非2的幂次可以在普通单败中使用轮空；若要同时做全员唯一排位，必须由规程明确预赛、轮空球队的排位权重和同名次处理，系统不能自行猜测。

#### 产品配置不得混用

建议后台将赛制保存为结构化配置：

```json
{
  "baseFormat": "group_then_knockout",
  "rankingMode": "full_placement",
  "groupCount": 4,
  "teamsPerGroup": 4,
  "qualifiersPerGroup": 2,
  "rankingLines": [
    { "range": "1-8", "sourceRanks": [1, 2] },
    { "range": "9-16", "sourceRanks": [3, 4] }
  ]
}
```

或：

```json
{
  "baseFormat": "single_elimination",
  "rankingMode": "champion_only",
  "teamCount": 16,
  "thirdPlaceMatch": true
}
```

`baseFormat`决定球队第一轮从哪里来；`rankingMode`决定负者是否继续排位。这两个字段不能用一个“淘汰赛”开关代替。

场次数量只来自赛制拓扑，不能用“比赛日数量 × 场地容量”反推或删减。容量不足时应产生“未排场次”，而不是删除正式场序。

## 五、自动排赛逻辑

### 1. 输入

自动排赛至少读取：

- 场序、阶段、轮次、组别、分组；
- 主客队来源，如真实球队、`A组第1`、`场序13胜者`；
- 前置场序和阶段顺序；
- 日期范围；
- 每片场地的适用组别、时长、缓冲和时间段；
- 同队比赛频次和最少休息规则；
- 关键比赛是否必须安排到主场地。

### 2. 生成资源格

系统先生成全部候选资源格：

```text
资源格 = 日期 × 可用场地 × 该场地的合法开赛时间
```

每个资源格只能被一场比赛占用。

### 3. 排序与落位

1. 按组别内的阶段依赖排序：小组赛或首轮淘汰 → 下一轮 → 半决赛/排位赛 → 决赛。
2. 逐场查找最早的合法资源格。
3. 小组赛优先使用白天时间，晚间放到后面。
4. 半决赛、决赛、三四名决赛等关键场次默认使用该组别的第一块主场地，并串行安排。
5. 找不到合法资源格时，将该场保留在“未排场次”中并记录原因。

## 六、必须阻止的冲突

自动排赛和手动调赛必须使用同一套校验：

1. 同一场地、同一日期、同一时间不能安排两场比赛。
2. 同一球队不能同时参加两场比赛。
3. 青少年篮球当前默认同一队在同一天的同一上午、下午或晚间最多1场。
4. 后续阶段必须晚于上一阶段的全部来源场次；不能出现小组赛未结束，半决赛已经开打。
5. 只允许把组别排入其适用场地。
6. 比赛必须完整落在一个时间段内，不能跨越午间或晚间边界。
7. 同一标准场地拆出的子场之间，以及整场和子场之间，必须遵守资源互斥关系。
8. 已开始或已结束的场次不能像普通待开赛场次一样直接拖拽；应走改期、作废或重赛流程并留下操作记录。

当前篮球实现用“同一时段最多1场”近似保障青少年休息。足球复用时应进一步显式保存 `minimumRestMinutes`，按上一场结束时间到下一场开赛时间进行分钟级校验。

## 七、容量与资源不足

### 1. 理论容量

```text
单场地每日容量 = 该场地所有合法开赛时间数量
每日总容量 = 所有启用场地每日容量之和
赛事理论容量 = 比赛日数量 × 每日总容量
```

理论容量只是上限。球队休息、阶段依赖、组别场地限制和关键场次串行会继续降低实际可排容量。

### 2. 资源不足时的处理顺序

1. 优先增加比赛日；
2. 必须压缩赛期时再开启晚间时段；
3. 延长上午或下午结束时间；
4. 在规程允许范围内缩短缓冲或提前首场；
5. 增加可用场地；
6. 如仍不足，调整赛制，但此操作必须明确提示会重建抽签、场序和赛程。

系统不得为了“全部排满”而绕过休息或阶段依赖。

## 八、手动调赛

- 日历固定显示全部启用场地，空时隙也保留。
- 比赛可以拖到空资源格，也可以与另一场比赛交换。
- 每次拖放前校验场地、时间边界、球队频次、休息和阶段依赖。
- 冲突提示要指出具体对象和原因，例如“U10男子组不适用2号场”“猎鹰队当日上午已有比赛”“场序13依赖的两场半决赛尚未结束”。
- 空资源格可手动添加场次，但必须通过结构化字段选择组别、阶段、轮次、主客来源，不能只输入一段自由文本。
- 调整日期或场地不改场序；场序继续作为对阵图、现场任务、赛果和报表的唯一关联键。

## 九、足球应直接复用的部分

足球可直接复用：

- 赛制与排赛分层；
- 场序和胜负来源引用；
- 小组循环、单败淘汰、三四名赛、全员排位的场次公式；
- 日期 × 场地 × 开赛时间的资源格模型；
- 阶段依赖、场地冲突、同队冲突；
- 未排场次和资源不足建议；
- 日历拖拽、交换、结构化新增和多视图同步。

## 十、足球必须单独配置的部分

以下内容不能照抄篮球默认值：

1. **比赛时长**：按五人制、七人制、八人制、十一人制及年龄组设置；上下半场、半场休息是否计入占场时间需要明确。
2. **换场缓冲**：足球可能需要退场、入场、热身、设备检查和补时余量。
3. **最少休息**：按年龄、比赛时长和当地规程配置，不要只用“上午/下午各一场”代替。
4. **场地拆分**：标准场可拆成多个小场，需要 `parentVenueId`、`exclusiveResourceGroup` 或等价字段处理整场与子场互斥。
5. **天气与照明**：增加雨雪、高温、雷电、草地养护和灯光可用性等场地状态。
6. **淘汰赛占场时间**：加时、点球大战会造成结束时间不确定，排赛容量应使用“常规比赛 + 最大加时/点球预留 + 缓冲”或配置风险余量。
7. **主客与场地转换**：同一球队连续比赛时，可把跨场地步行或交通时间计入最少休息。

足球参数建议作为赛事模板初始化，不应写死在排赛算法中。例如可以建立“五人制青少年”“七人制青少年”“十一人制成人”等模板，模板只预填时长、缓冲、休息和场地类型，主办方保存规程时再次确认。

## 十二、足球复用的验收清单

1. 不同年龄组能使用不同场地、时长、缓冲和休息时间。
2. 标准场拆成多个小场后，整场与子场不会同时被占用。
3. 同队不会同时比赛，也不会在最少休息未满足时再次开赛。
4. 淘汰赛不会早于其全部来源比赛。
5. 比赛不会跨越时间段结束线。
6. 理论容量不足时保留未排场次并给出原因，不自动删除场次。
7. 拖拽、交换和手动新增使用与自动排赛相同的冲突校验。
8. 保存后，赛事日历、组别竞赛日程、现场任务、赛果和对阵图读取同一场序。
9. 修改时间或场地不改变场序；修改赛制时明确提示清空范围。
10. 加时、点球、天气中断和改期均有可追溯的状态与操作记录。

## 十三、建议交给足球项目的实施顺序

1. 先复用赛制拓扑、场序、来源和比赛总场数计算。
2. 再建立足球场地模板、整场/子场互斥和时间段配置。
3. 接入分钟级最少休息与最大占场时间。
4. 接入自动排赛和未排原因。
5. 最后接入日历拖拽、交换、改期、天气中断和多视图同步。

足球项目不应直接复制篮球页面中的演示场馆、篮球年龄组时长或半场命名；应复用数据模型与约束，再替换项目参数和文案。

## 十四、PC端竞赛日程的三层输出

足球端复用时，应把“赛程数据”“后台操作日历”和“正式竞赛日程文件”分成三层，三者读取同一份场序，但职责不同：

1. **赛程数据层**：保存完整场序、对阵来源、日期、时间、场地、依赖和状态，是唯一事实来源。
2. **赛事日历层**：供赛事管理员拖拽、交换、改期、处理冲突和查看空时隙，强调可操作性。
3. **正式竞赛日程层**：供参赛队、裁判、场馆和工作人员查看、打印和留档，强调静态版式、可追溯场序和A4输出。

正式竞赛日程不能从页面文字临时拼出另一份数据。它必须由已经保存的赛程数据投影生成；打印、Excel、PDF和页面预览使用同一个标准化行数组。

```text
赛制拓扑 -> 自动/手动排赛 -> 保存标准赛程 -> 标准化竞赛日程行
                                            ├─ PC预览
                                            ├─ A4打印 / 另存PDF
                                            └─ A4 Excel
```

## 十五、正式竞赛日程表结构

### 1. 按竞赛组别独立成表

- 一个竞赛组别生成一份独立日程，例如“U10男子组”“U12女子组”，不同组别不混在同一份正式文件中。
- `组别`与`分组`必须分列。“U10男子组”是竞赛组别，“A组/B组”是循环赛分组。
- 页面通过组别标签切换；打印和导出只处理当前组别。
- 页面存在阶段、轮次、分组、球队、场地、状态筛选时，打印和导出遵循当前筛选结果。若要导出该组全部场次，应先清除筛选。
- 文件标题、总场数、场馆摘要必须根据当前输出行重新计算，不能继续显示全赛事数量。

### 2. 固定八列

| 列 | 字段建议 | 展示规则 |
| --- | --- | --- |
| 日期 | `date` | `YYYY-MM-DD`或统一中文日期；连续相同日期可合并单元格。 |
| 时间 | `startTime` | 统一使用24小时制 `HH:mm`。 |
| 轮次 | `roundName` | 如“第1轮”“1/4决赛”“5-8名排位赛”；同一日期内连续相同轮次可合并。 |
| 组别 | `competitionGroup` | 如“U10男子组”，不得塞入A/B组。 |
| 分组 | `pool` | 如“A组”；无分组显示“—”或留空，全项目统一一种口径。 |
| 比赛队 | `homeDisplay/awayDisplay` | 使用“主队 VS 客队”；未产生球队时显示可追溯来源。 |
| 场地 | `courtDisplay` | 正文只显示简短场地号，如“1”“A”；完整场馆名放在表头摘要。 |
| 场序 | `competitionSerial` | 当前竞赛组别内从1连续编号，居中显示，是跨模块关联键。 |

### 3. 对阵来源文案

- 已确定球队：直接显示真实队名。
- 小组出线来源：显示 `A组第1`、`B组第2`。
- 淘汰赛来源：显示 `场序13胜者`、`场序14负者`。
- 轮空只用于赛制计算，不生成一行“轮空比赛”。
- 禁止使用“待定1”“胜者线待定”“第X名待定”等无法回溯的正式文案。

### 4. 表头和表尾

正式文件至少包含：

- 品牌/项目标识，如“赛小蜂足球 · 正式竞赛文件”；
- 标题，如“竞赛日程（U10男子组）”；
- 赛事名称和当前表内总场数；
- 场馆名称摘要，不重复冗长的球场信息；
- 制表日期；
- 固定提示：“比赛时间与场地以主办方最新发布的竞赛日程为准。”

## 十六、A4横版与竖版规则

### 1. 方向选择

- 页面提供明确的 `A4竖版`、`A4横版`切换，不使用含义模糊的“紧凑/宽屏”。
- 默认采用A4竖版；队名较长、场地较多或列内容较宽时，管理员可切换横版。
- 当前方向同时控制页面纸张预览、浏览器打印和Excel页面设置，三个出口不得各自保存不同方向。
- 文件名必须体现方向，例如：`赛事名-竞赛日程-A4竖版.xlsx`、`赛事名-竞赛日程-A4横版.xlsx`。

### 2. 页面纸张尺寸

```text
A4竖版：210mm × 297mm
A4横版：297mm × 210mm
打印页边距：9mm（足球端可配置，但页面、打印和Excel必须保持一致）
```

PC预览区域按真实A4宽高比显示，不能只缩窄表格假装竖版：

```css
.schedule-sheet.portrait  { width: 210mm; min-height: 297mm; }
.schedule-sheet.landscape { width: 297mm; min-height: 210mm; }
@media print {
  @page { size: A4 var(--orientation); margin: 9mm; }
}
```

实际实现时，`@page`中的方向建议由页面生成单独样式：

```js
const orientation = selected === 'landscape' ? 'landscape' : 'portrait';
const pageStyle = `@media print{@page{size:A4 ${orientation};margin:9mm}}`;
```

不要仅依赖页面上某个class改变宽度，因为浏览器打印方向由 `@page size` 决定。

### 3. 列宽建议

Excel列宽可使用以下篮球现行值作为足球初始值，再通过真实长队名测试调整：

```js
const widths = orientation === 'portrait'
  ? [9, 9, 11, 14, 8, 30, 10, 7]
  : [11, 11, 14, 17, 9, 43, 11, 7];
```

顺序对应：日期、时间、轮次、组别、分组、比赛队、场地、场序。比赛队列获得最多空间；场序列最窄并居中。足球队名普遍较长时，应优先扩大比赛队列或切换横版，不应通过极小字号硬塞。

### 4. 多页规则

- 一页放不下时允许自然分页，禁止纵向压缩到一页导致文字不可读。
- 横向始终压缩为1页宽；纵向页数不限制。
- 每一页重复八列表头。
- 标题区只在第一页显示；续页至少重复列头，并通过页眉或打印标题保留赛事名和组别信息。
- 日期、轮次合并只合并当前连续行。若合并区域跨打印页影响可读性，导出层应在分页边界拆开合并并在下一页重复值。
- 单场比赛行不能被拆成两页；长队名允许换行，但主客队和 `VS` 必须保持在同一个单元格。

## 十七、浏览器打印与PDF方法

### 1. 打印流程

1. 从当前页面取得已经渲染的正式日程区域，而不是打印整个后台。
2. 打开独立打印预览窗口。
3. 加载正式日程样式，并注入当前A4方向的 `@page` 规则。
4. 只复制当前组别、当前筛选结果的日程区域。
5. 预览窗口保留“打印”和“关闭”按钮；进入实际打印媒体后隐藏工具条。
6. 调用浏览器打印；用户可选择实体打印机或“另存为PDF”。

```js
function openSchedulePrint({ sheetHtml, orientation, stylesheetUrl }) {
  const direction = orientation === 'landscape' ? 'landscape' : 'portrait';
  const popup = window.open('', '_blank', 'popup=yes,width=1100,height=850');
  if (!popup) throw new Error('PRINT_POPUP_BLOCKED');

  popup.document.write(`<!doctype html>
    <html lang="zh-CN"><head><meta charset="UTF-8">
    <link rel="stylesheet" href="${stylesheetUrl}">
    <style>
      @page{size:A4 ${direction};margin:9mm}
      @media print{.print-toolbar{display:none!important}}
    </style></head>
    <body><div class="print-toolbar">打印 / 关闭</div>${sheetHtml}</body></html>`);
  popup.document.close();
  popup.focus();
}
```

### 2. 打印安全规则

- 后台侧栏、顶部导航、筛选器、方向切换、按钮、提示弹窗不得进入打印内容。
- 白色纸张、黑色文字、清晰表格线为默认；状态颜色不能成为识别场次的唯一方式。
- 字体优先使用宋体或系统可用中文衬线字体，缺字时回退到系统中文字体。
- 新窗口被拦截时要给出明确提示，不能静默失败。
- 打印预览应在样式加载完成后再触发打印；自动打印失败时仍保留手动打印按钮。
- 生成PDF沿用同一打印入口，避免另维护一套PDF排版逻辑。

## 十八、A4 Excel导出方法

### 1. 工作簿页面设置

以ExcelJS为例，A4的 `paperSize` 为 `9`：

```js
const worksheet = workbook.addWorksheet('竞赛日程', {
  views: [{ showGridLines: false, zoomScale: 100 }],
  pageSetup: {
    paperSize: 9,
    orientation,            // portrait / landscape
    fitToPage: true,
    fitToWidth: 1,
    fitToHeight: 0,
    horizontalCentered: true,
    margins: {
      left: 0.35, right: 0.35,
      top: 0.35, bottom: 0.35,
      header: 0.15, footer: 0.15
    }
  }
});
```

`fitToWidth: 1`保证八列只占一页宽；`fitToHeight: 0`允许纵向自然分页。不要把 `fitToHeight` 设置为1，否则几十场比赛会被缩成无法阅读的一页。

### 2. 推荐行结构

```text
第1行：品牌/项目标识，A1:H1合并
第2行：竞赛日程标题，A2:H2合并
第3行：赛事名称与本表场次数，A3:H3合并
第4行：场馆摘要，A4:H4合并
第5行：八列表头
第6行起：比赛数据
最后一行：左侧备注A:D合并，右侧制表日期E:H合并
```

- 第5行设置为重复打印标题：`printTitlesRow = '5:5'`。
- 打印区域设置为 `A1:H最后一行`。
- 关闭工作表网格线，依靠正式表格边框。
- 外框可用中线，内部用细线；全部数据单元格垂直居中并允许换行。
- 比赛队单元格统一输出 `主队  VS  客队`，不依赖HTML节点或图标。

### 3. 合并单元格算法

网页日程对连续相同日期、同日期内连续相同轮次使用 `rowspan`。导出Excel时必须把这些合并关系转换为真实Excel合并区域，而不是只在第一行写值。

```js
const occupied = Array(8).fill(0);

for (const [rowIndex, htmlRow] of htmlRows.entries()) {
  const excelRow = rowIndex + 6;
  let column = 1;

  for (const htmlCell of htmlRow.cells) {
    while (occupied[column - 1] > 0) column += 1;
    const rowSpan = Math.max(1, Number(htmlCell.rowSpan || 1));
    const colSpan = Math.max(1, Number(htmlCell.colSpan || 1));

    worksheet.getCell(excelRow, column).value = normalizeCellValue(htmlCell);
    if (rowSpan > 1 || colSpan > 1) {
      worksheet.mergeCells(
        excelRow,
        column,
        excelRow + rowSpan - 1,
        column + colSpan - 1
      );
    }

    for (let offset = 0; offset < colSpan; offset += 1) {
      occupied[column - 1 + offset] = rowSpan;
    }
    column += colSpan;
  }

  for (let i = 0; i < occupied.length; i += 1) {
    occupied[i] = Math.max(0, occupied[i] - 1);
  }
}
```

如果足球端不从HTML导出，而是直接从标准行数组生成Excel，应优先直接计算日期和轮次的连续区间，这样更稳定，也便于做分页边界拆分。

### 4. 下载与错误处理

- MIME类型：`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。
- 文件名中的 `\\ / : * ? " < > |` 必须替换，避免Windows下载失败。
- 生成后及时释放临时对象URL。
- Excel组件未加载、无可导出行或生成失败时，必须显示中文错误提示。
- 导出工作簿的创建者改为足球项目品牌，不能继续写“赛小蜂篮球”。

## 十九、建议的通用方法拆分

足球项目不宜复制一个数千行页面脚本。建议把赛程与导出拆为以下纯函数或服务：

| 方法 | 职责 |
| --- | --- |
| `buildCompetitionTopology(config, teams, drawState)` | 生成场序、轮次、主客来源和依赖，不处理日期场地。 |
| `buildResourceSlots(dates, venues, ruleTemplate)` | 生成日期×场地×合法时间的资源格。 |
| `assignMatches(topology, slots, constraints)` | 自动落位并输出已排与未排场次。 |
| `validateAssignment(match, slot, context)` | 自动排赛、拖拽、交换共用的冲突校验。 |
| `normalizeScheduleRows(savedMatches)` | 生成页面、打印和Excel共同使用的八列标准行。 |
| `groupContinuousRows(rows, keyFn)` | 计算日期、轮次的连续合并区间。 |
| `renderScheduleSheet(rows, options)` | 生成当前组别、方向和品牌下的正式预览。 |
| `openSchedulePrint(sheet, options)` | 生成A4打印预览并支持另存PDF。 |
| `exportScheduleWorkbook(rows, options)` | 生成A4横/竖版Excel。 |

```json
    "team": "all",
    "venue": "all",
    "status": "all"
  }
}
```

## 二十、足球端专项补充字段

为支持足球排赛和打印，建议在篮球通用字段之外增加：

```json
{
  "sportFormat": "7v7",
  "regularMinutes": 40,
  "halftimeMinutes": 10,
  "extraTimeReserveMinutes": 10,
  "penaltyReserveMinutes": 10,
  "turnoverBufferMinutes": 10,
  "occupancyMinutes": 80,
  "minimumRestMinutes": 120,
  "weatherStatus": "normal",
  "lightingRequired": false,
  "parentFieldId": "field-1",
  "exclusiveResourceGroup": "field-1-footprint"

```

其中：

```text
占场时长 = 常规比赛 + 中场休息 + 加时预留 + 点球预留 + 换场缓冲
```

循环赛通常不需要加时和点球预留；淘汰赛是否预留由竞赛规程决定。正式日程表展示计划开赛时间即可，但排赛引擎必须用占场时长判断下一场是否能合法开始。

## 二十一、A4打印与导出验收清单

1. 页面可在A4竖版和横版之间切换，预览比例分别接近 `210:297` 和 `297:210`。
2. 当前方向能同步影响浏览器打印和Excel `orientation`。
3. 正式表固定为日期、时间、轮次、组别、分组、比赛队、场地、场序八列。
4. 每个竞赛组别独立预览、打印和导出，不混入其他组别。
5. 页面存在筛选时，标题场次数、正文、打印和Excel使用相同结果。
6. 日期和轮次的连续合并在网页与Excel中一致，场序仍按正式数据展示。
7. 淘汰赛使用 `场序X胜者/负者`，小组出线使用 `A组第X`，不存在不可追溯的“待定”文案。
8. Excel为真实XLSX文件，A4纸张、1页宽、纵向不限页，并在每页重复第5行表头。
9. 浏览器打印不包含后台导航、筛选器、按钮、弹窗和方向切换器。
10. 长队名可以换行但不截断；横版时比赛队列明显宽于竖版。
11. 新窗口被拦截、Excel组件缺失、无数据和导出失败都有明确提示。
12. 文件名包含赛事名、竞赛日程、A4方向，并清理Windows非法字符。
13. 打印或导出不会修改赛程、场序、状态和任何业务数据。
14. 足球品牌、项目名、时长和场地命名均来自配置，不残留篮球文案或默认值。

## 二十二、足球端赛制生成器实现口径

### 1. 先生成拓扑，再安排时间场地

赛制生成器只负责以下内容：

- 生成比赛和组别内连续场序；
- 确定每场的主客来源；
- 确定胜者、负者进入哪一场；
- 标记阶段、轮次和名次区间；
- 生成前置依赖。

赛制生成阶段不得写死比赛日期、开赛时间或场地。时间和场地由排赛引擎在拓扑生成完成后处理。

### 2. 来源必须结构化

不能只保存“场序25胜者”这一段文字。正式数据应保存来源类型和来源编号，再由显示层生成中文：

```json
{
  "type": "group_rank",
  "groupId": "A",
  "rank": 1
}
```

```json
{
  "type": "match_result",
  "matchNo": 25,
  "outcome": "winner"
}
```

```json
{
  "type": "seed",
  "seedNo": 1,
  "teamId": "team-001"
}
```

显示层分别输出 `A组第1`、`场序25胜者` 和真实球队名。

### 3. 每场比赛的数据结构

```json
{
  "matchNo": 41,
  "baseFormat": "group_then_knockout",
  "rankingMode": "full_placement",
  "phase": "placement",
  "roundName": "9—12名排位半决赛",
  "placementRange": [9, 12],
  "homeSource": {
    "type": "match_result",
    "matchNo": 37,
    "outcome": "winner"
  },
  "awaySource": {
    "type": "match_result",
    "matchNo": 38,
    "outcome": "winner"
  },
  "dependencyMatchNos": [37, 38],
  "winnerDestination": {
    "matchNo": 45,
    "side": "home"
  },
  "loserDestination": {
    "matchNo": 46,
    "side": "home"
  }
}
```

`winnerDestination`和`loserDestination`用于结果回填和对阵图连线；即使可以从下一场的来源反查，也建议显式保存或在发布拓扑时计算并校验。

### 4. 小组赛 + 淘汰赛生成步骤

```text
输入球队、分组数量、每组队数、每组出线数和排名方式
  -> 为每组生成单循环场次
  -> 生成小组排名来源，不提前填入实际球队
  -> 根据sourceRanks把小组名次分入1—8、9—16等名次线
  -> 按跨组交叉模板生成各名次线首轮
  -> 若为全员排位，对每条名次线递归生成胜者线和负者线
  -> 生成最终名次赛
  -> 校验所有球队来源恰好进入一条名次线
```

拓扑可以在小组赛开始前预生成，但淘汰场次的球队仍应保持 `group_rank` 来源；小组排名正式确认后再解析为实际球队。不得在小组赛未结束时把临时排名球队固化到淘汰场次。

### 5. 单败淘汰生成步骤

```text
输入球队、种子顺序、排名方式和是否设置三四名赛
  -> 计算签表规模
  -> 按种子/抽签规则生成第一轮真实球队来源
  -> 普通单败只把胜者连接到下一轮
  -> 全员排位同时连接胜者去向和负者去向
  -> 生成决赛或全部最终名次赛
```

普通单败的负者没有 `loserDestination`。全员排位中的每一场，除最终名次赛外，都必须同时存在胜者和负者去向。

### 6. 8队名次线生成模板

无论这8队来自小组赛前两名、小组赛未出线球队，还是单淘签位，进入某条连续8个名次的排位线后都使用同一模板。设该名次线起始名次为 `R`：

```text
首轮4场
  -> 胜者4队：竞争 R 至 R+3
  -> 负者4队：竞争 R+4 至 R+7

第二轮4场
  -> 高区两场：胜者争 R/R+1，负者争 R+2/R+3
  -> 低区两场：胜者争 R+4/R+5，负者争 R+6/R+7

最终4场
  -> R、R+1名排位赛
  -> R+2、R+3名排位赛
  -> R+4、R+5名排位赛
  -> R+6、R+7名排位赛
```

当 `R = 1` 时得到1—8名；当 `R = 9` 时得到9—16名。足球端应复用同一个函数，不要分别手写两套逻辑。

### 7. 建议函数接口

```js
buildGroupStage(groups, teams)
buildCrossGroupSources(groupRankSources, crossTemplate)
buildPlacementLine({ sources, rankStart, matchNoStart })
buildSingleElimination({ seededTeams, rankingMode, thirdPlaceMatch })
linkResultDestinations(matches)
validateCompetitionTopology(matches, config)
```

其中 `buildPlacementLine`应返回：

```json
{
  "matches": [],
  "nextMatchNo": 49,
  "finalRanks": {
    "1": "场序33胜者",
    "2": "场序33负者"
  }
}
```

## 二十三、赛制生成必须通过的测试

### 1. 16队小组赛 + 淘汰赛全员排位

- 4组×4队的小组赛必须为24场。
- 每组第1、第2名只能进入1—8名线。
- 每组第3、第4名只能进入9—16名线。
- 1—8名线必须为12场，9—16名线必须为12场。
- 总场数必须为48场。
- 16支球队各自路径必须为3场小组赛+3场排位赛。
- 最终必须产生1—16共16个唯一名次，不能缺失或重复。
- 冠军线第一轮必须显示1/4决赛，不能因赛事总数为16队而显示1/8决赛。

### 2. 16队普通单败淘汰

- 第一轮必须为1/8决赛8场。
- 后续依次为1/4决赛4场、半决赛2场、决赛1场。
- 不含三四名赛时共15场，包含三四名赛时共16场。
- 除三四名赛外，任何负者都不能进入下一场。
- 第一轮来源必须是球队或种子签位，不能出现小组名次来源。

### 3. 16队单淘全员排位

- 总场数必须为32场。
- 第一轮8场的胜者进入1—8名范围，负者进入9—16名范围。
- 非最终名次赛必须同时具有胜者去向和负者去向。
- 每支球队必须参加4场，并产生1—16的唯一名次。

### 4. 通用拓扑校验

- 场序连续且不重复。
- 每个 `match_result` 来源引用的场序必须早于当前场序。
- 同一来源结果不能被错误地送入两个互斥席位。
- 每场的两个来源不能相同。
- 所有最终名次必须各有唯一决定场次。
- 普通单败和全员排位的预期场数必须分别按各自公式计算。
- 赛制拓扑改变时必须生成新版本并提示重建赛程；仅调整时间场地时不能改变场序。
